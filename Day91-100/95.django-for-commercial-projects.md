## Using Django for Commercial Projects

This lesson is a large practical review of the knowledge needed to build real Django systems. It functions more like a field guide or interview-oriented project checklist than a single narrow tutorial.

### Web Applications

You should be able to explain:

1. how a web application works end to end
2. the physical architecture of a deployed system
3. the Django request-response cycle

Typical production architecture may include:

- reverse proxy / load balancer
- application servers
- database servers
- file servers
- mail servers
- cache servers
- firewalls

### MVC / MTV

Core question: why use MVC or MTV?

Main answer:

- decouple data, presentation, and control flow

In Django terms:

- Model = data
- Template = presentation
- View = request-handling logic

### HTTP Requests and Responses

You should understand:

- request line, headers, body
- response line, headers, body
- status-code classes (`1xx` to `5xx`)
- common Django `HttpRequest` and `HttpResponse` APIs

Useful request APIs:

- `method`
- `path`
- `get_full_path()`
- `GET`
- `POST`
- `FILES`
- `COOKIES`
- `META`
- `body`
- `session`
- `user`

Useful response APIs:

- `set_cookie`
- `set_signed_cookie`
- `delete_cookie`
- headers via mapping syntax
- `status_code`
- `content`

### Data Models

Topics to know:

- relational design basics
- normalization and denormalization

- migrations
- ORM CRUD operations

### Middleware

You should understand:

- what middleware is

Important areas:

### Caching and Redis

Key topics:

Important types of testing include:

### Practical Value of the Lesson

This lesson is essentially a commercial Django project checklist. The key point is not memorizing isolated framework APIs, but understanding how all of the pieces fit together in a production system.
