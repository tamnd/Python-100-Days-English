## Designing Network APIs

Good API design is about clarity, consistency, and long-term maintainability.

Important aspects:

1. resource-oriented URLs
2. HTTP method semantics
3. status codes
4. pagination and filtering
5. authentication and authorization
6. versioning
7. documentation

Good API responses should usually avoid ambiguous null-heavy designs when possible, because those create unnecessary complexity for clients.

A useful API document normally includes:

- purpose
- URL
- method
- request parameters
- response format
- status codes
- examples

The original lesson emphasizes that API documentation is part of the interface itself, not an afterthought.
