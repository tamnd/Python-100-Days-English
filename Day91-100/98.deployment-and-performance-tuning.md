## Deployment and Performance Tuning

### Preparing for Launch

Before going live, the lesson recommends first doing deployment checks:

```shell
python manage.py check --deploy
```

Then update production settings:

```python
DEBUG = False
ALLOWED_HOSTS = ['*']
```

The lesson also lists several security-related settings:

```python
SECURE_HSTS_SECONDS = 3600
SECURE_HSTS_INCLUDE_SUBDOMAINS = True
SECURE_HSTS_PRELOAD = True

SECURE_SSL_REDIRECT = True
SECURE_CONTENT_TYPE_NOSNIFF = True
SECURE_BROWSER_XSS_FILTER = True

SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True

X_FRAME_OPTIONS = 'DENY'
```

Sensitive information should be moved into environment variables or external files:

```python
SECRET_KEY = os.environ['SECRET_KEY']
DB_USER = os.environ['DB_USER']
DB_PASS = os.environ['DB_PASS']
REDIS_AUTH = os.environ['REDIS_AUTH']
```

### Upgrading the Server Python Environment

The lesson uses CentOS as an example for installing Python 3 from source without breaking the system Python 2 environment. The rough process is:

1. Install low-level dependency libraries.
2. Download Python source code.
3. Verify the archive.
4. Extract it.
5. Run `./configure`.
6. Run `make && make install`.
7. Update the `PATH`.
8. Optionally create symbolic links.
9. Verify both `python3` and `python`.

### Project Directory Structure

The lesson proposes a project layout with separate directories for:

- code;
- configuration;
- logs;
- static resources;
- virtual environment.

It also notes that:

- HTTPS certificates can be stored under `conf/cert`;
- project code can be checked out into the `code` directory;
- the virtual environment can be created with `venv`, `virtualenv`, `pyenv`, or similar tools.

The deployment walkthrough also touches on domain registration, record filing, DNS resolution, certificate purchase, code checkout, virtual-environment creation, and dependency installation.

### uWSGI Configuration

The lesson installs `uWSGI` with:

```shell
pip install uwsgi
```

Then it configures an `uwsgi.ini` file that includes:

- the base project path;
- the project name;
- daemon and process settings;
- the virtual-environment path;
- the Django code directory;
- the Python interpreter path;
- the WSGI module;
- the socket address and port;
- the log file path.

Finally, the server can be started with:

```shell
nohup uwsgi --ini conf/uwsgi.ini &
```

### Nginx Configuration

The lesson then moves to Nginx. First install it:

```shell
yum -y install nginx
```

Then configure the global `nginx.conf` with the usual items:

- user;
- worker processes;
- error log;
- `events` settings such as `epoll` and `worker_connections`;
- the `http` block;
- log format;
- access log;
- `sendfile`, `tcp_nopush`, `tcp_nodelay`;
- keepalive timeout;
- MIME configuration;
- inclusion of extra config files.

Then create a local project-level Nginx config that:

- listens on both `80` and `443`;
- proxies dynamic requests to uWSGI;
- serves static files directly;
- configures SSL certificates and SSL options for HTTPS.

When configuration changes are made, Nginx can be reloaded or restarted:

```shell
nginx -s reload
```

or

```shell
systemctl restart nginx
```

The lesson also reminds readers that `python manage.py collectstatic` can collect static files into a dedicated directory if `STATIC_ROOT` is configured.

### Load Balancing

The lesson then introduces load balancing with Nginx. It even shows running multiple Nginx containers:

```shell
docker run -d -p 801:80 --name nginx1 nginx:latest
docker run -d -p 802:80 --name nginx2 nginx:latest
docker run -d -p 803:80 --name nginx3 nginx:latest
```

and using an `upstream` block in Nginx to distribute traffic among multiple backend servers with weights.

It notes that Nginx uses weighted round-robin by default, but also supports strategies such as `ip_hash`, `fair`, and `url_hash`, along with status and control parameters like `backup`, `down`, `fail_timeout`, `max_fails`, and `weight`.

### Keepalived

When Nginx is used as a load balancer, the load-balancing server itself can fail. To solve that, the lesson mentions using Keepalived for hot failover between a primary and standby load balancer, so the system maintains high availability.

### MySQL Master-Slave Replication

The lesson also demonstrates MySQL master-slave replication with Docker. The basic idea is:

1. Prepare MySQL configuration files and directories for data and logs.
2. Run separate master and slave containers with mounted volumes.
3. Give each server a different `server-id`.
4. Configure replication users and replication settings.

This is shown as part of the broader theme that deployment is not only about getting a single process to run. It is about availability, scaling, and operational discipline.

### Summary

This lesson ties deployment and performance work together. It covers production checks, security settings, Python environment preparation, directory layout, uWSGI, Nginx, HTTPS, load balancing, failover, and database replication. The main point is that deployment is not just “make it run once.” It is about making a system stable, secure, maintainable, and ready for real traffic.
