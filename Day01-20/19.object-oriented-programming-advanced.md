## Advanced Object-Oriented Programming

In the previous lesson, we introduced the basics of object-oriented programming in Python. In this lesson, we continue with more advanced OOP topics.

### Visibility and Property Decorators

In many object-oriented languages, object attributes are often private or protected, meaning they should not be accessed directly. Methods, on the other hand, are usually public because they form the external interface through which objects receive messages.

In Python, a naming convention is used to suggest visibility:

- `__name` suggests a private attribute
- `_name` suggests a protected attribute

```python
class Student:

    def __init__(self, name, age):
        self.__name = name
        self.__age = age

    def study(self, course_name):
        print(f'{self.__name} is studying {course_name}.')


stu = Student('Wang Dachui', 20)
stu.study('Python Programming')
# print(stu.__name)  # AttributeError
```

The last line raises `AttributeError`. However, most people who use Python, when defining classes, usually do not choose to make object attributes private or protected. As one famous saying goes, "**We are all consenting adults here**." Adults can be responsible for their own behavior, and they do not need Python itself to impose access restrictions. In fact, most programmers believe that **open is better than closed**, and making object attributes private is not absolutely necessary. That is why Python does not impose the strictest possible semantic limitation. In other words, if you really want to, you can still access the private attribute `__name` above using `stu._Student__name`.

### Dynamic Attributes

Python is a dynamic language. One consequence is that we can add attributes to objects at runtime.

```python
class Student:

    def __init__(self, name, age):
        self.name = name
        self.age = age


stu = Student('Wang Dachui', 20)
stu.sex = 'male'
```

If you want to prevent arbitrary new attributes from being added, use `__slots__`.

```python
class Student:
    __slots__ = ('name', 'age')

    def __init__(self, name, age):
        self.name = name
        self.age = age


stu = Student('Wang Dachui', 20)
# stu.sex = 'male'  # AttributeError
```

### Static Methods and Class Methods

So far, all methods we have defined are instance methods. In addition, a class can also have **static methods** and **class methods**. These are messages sent to the class itself rather than to an instance.

Consider a `Triangle` class. Calculating perimeter and area are clearly instance behaviors. But checking whether three side lengths can form a triangle does not require an existing triangle object, so that logic is better placed in a static method or class method.

```python
class Triangle(object):
    """Triangle"""

    def __init__(self, a, b, c):
        self.a = a
        self.b = b
        self.c = c

    @staticmethod
    def is_valid(a, b, c):
        """Check whether three sides can form a triangle."""
        return a + b > c and b + c > a and a + c > b

    def perimeter(self):
        return self.a + self.b + self.c

    def area(self):
        p = self.perimeter() / 2
        return (p * (p - self.a) * (p - self.b) * (p - self.c)) ** 0.5


if Triangle.is_valid(3, 4, 5):
    t = Triangle(3, 4, 5)
    print(f'Perimeter: {t.perimeter()}')
    print(f'Area: {t.area()}')
else:
    print('Invalid side lengths!')
```

Static methods and class methods can both be called with `ClassName.method_name(...)`. The difference is that the first parameter of a class method is the class object itself, while a static method has no such parameter. To summarize briefly, **instance methods, class methods, and static methods can all be called in the form `ClassName.method_name(...)`; the difference is whether the first parameter is an ordinary object, a class object, or there is no receiving object at all**. Static methods can usually also be written directly as independent functions, because they are not bound to a specific object.

We can also turn methods into properties with the `@property` decorator:

```python
class Triangle(object):
    """Triangle"""

    def __init__(self, a, b, c):
        self.a = a
        self.b = b
        self.c = c

    @staticmethod
    def is_valid(a, b, c):
        return a + b > c and b + c > a and a + c > b

    @property
    def perimeter(self):
        return self.a + self.b + self.c

    @property
    def area(self):
        p = self.perimeter / 2
        return (p * (p - self.a) * (p - self.b) * (p - self.c)) ** 0.5


if Triangle.is_valid(3, 4, 5):
    t = Triangle(3, 4, 5)
    print(f'Perimeter: {t.perimeter}')
    print(f'Area: {t.area}')
else:
    print('Invalid side lengths!')
```

### Inheritance and Polymorphism

Object-oriented languages let us create new classes based on existing ones. The class being inherited from is called the **parent class** (or base class), and the class that inherits is the **child class** (or derived class).

For example, students and teachers share many common properties and behaviors, because both are people. So we can first define a `Person` class and then derive `Student` and `Teacher` from it.

```python
class Person:
    """Person"""

    def __init__(self, name, age):
        self.name = name
        self.age = age

    def eat(self):
        print(f'{self.name} is eating.')

    def sleep(self):
        print(f'{self.name} is sleeping.')


class Student(Person):
    """Student"""

    def __init__(self, name, age):
        super().__init__(name, age)

    def study(self, course_name):
        print(f'{self.name} is studying {course_name}.')


class Teacher(Person):
    """Teacher"""

    def __init__(self, name, age, title):
        super().__init__(name, age)
        self.title = title

    def teach(self, course_name):
        print(f'{self.name} {self.title} is teaching {course_name}.')


stu1 = Student('Bai Yuanfang', 21)
stu2 = Student('Di Renjie', 22)
tea1 = Teacher('Wu Zetian', 35, 'Associate Professor')
stu1.eat()
stu2.sleep()
tea1.eat()
stu1.study('Python Programming')
tea1.teach('Python Programming')
stu2.study('Introduction to Data Science')
```

If a class does not explicitly specify a parent class, it inherits from `object` by default. `object` is Python's top-level base class.

A child class can also **override** methods inherited from the parent class. Different child classes can provide different implementation versions of the same method from the parent class. Methods like that exhibit polymorphic behavior at runtime, meaning that calling the same method does different things. Polymorphism is the most essential part of object-oriented programming, and of course it is also one of the hardest parts for beginners to truly understand and use flexibly.

### Summary

Python is a dynamically typed language, and objects in Python can have attributes added dynamically. The methods of an object are also attributes in essence, except that the attribute corresponds to a callable function. In the object-oriented world, **everything is an object**, and even **classes can receive messages**. Through inheritance, we **can create new classes from existing classes**, thereby reusing the code of existing classes.
