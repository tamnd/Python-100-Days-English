## Advanced Function Applications

In the previous lesson, we explored higher-order functions. In this lesson, we will continue with two important topics related to functions in Python: **decorators** and **recursion**.

### Decorators

In Python, a decorator is a language feature that **uses one function to wrap another function and give it extra capabilities**. A decorator itself is a function. Its parameter is the function being decorated, and its return value is a new function with the added behavior.

Consider two functions, `download` and `upload`, which simulate downloading and uploading files.

```python
import random
import time


def download(filename):
    """Download a file."""
    print(f'Start downloading {filename}.')
    time.sleep(random.random() * 6)
    print(f'{filename} download completed.')


def upload(filename):
    """Upload a file."""
    print(f'Start uploading {filename}.')
    time.sleep(random.random() * 8)
    print(f'{filename} upload completed.')


download('MySQL_Full_Crash_Course.avi')
upload('Python_From_Beginner_To_Hospitalized.pdf')
```

Now there is a new requirement: we want to know exactly how much time calling `download` and `upload` takes. How should we do that? Many readers have probably already thought of it: we can record one time when the function begins execution, record another time after the function call ends, and then subtract the two to compute the time spent on downloading or uploading, as shown below.

```python
start = time.time()
download('MySQL_Full_Crash_Course.avi')
end = time.time()
print(f'Time spent: {end - start:.2f} seconds')
start = time.time()
upload('Python_From_Beginner_To_Hospitalized.pdf')
end = time.time()
print(f'Time spent: {end - start:.2f} seconds')
```

Through the code above, we can record the time spent downloading and uploading files, but you may have noticed that the code for recording the time, calculating the duration, and displaying it is all duplicate code. People with programming experience know that **duplicate code is the source of all evil**, so is there a simple and elegant way to record function execution time without writing repeated code? In Python, decorators are the best solution to this kind of problem. Through decorator syntax, we can encapsulate the timing code, which is unrelated to the original business of uploading and downloading, into a function. If the `upload` and `download` functions need timing, we simply apply the decorator to those two functions.

The basic structure looks like this:

```python
def record_time(func):

    def wrapper(*args, **kwargs):

        result = func(*args, **kwargs)

        return result

    return wrapper
```

The parameter `func` is the function being decorated. The inner `wrapper` function is the enhanced version. Because `wrapper` will replace `func`, it accepts arbitrary positional and keyword arguments and passes them through unchanged.

Now let us add the timing behavior:

```python
import time


def record_time(func):

    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f'{func.__name__} execution time: {end - start:.2f} seconds')
        return result

    return wrapper
```

One way to use the decorator is:

```python
download = record_time(download)
upload = record_time(upload)
download('MySQL_Full_Crash_Course.avi')
upload('Python_From_Beginner_To_Hospitalized.pdf')
```

Python also offers syntactic sugar for decorators using `@decorator_name`:

```python
import random
import time


def record_time(func):

    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f'{func.__name__} execution time: {end - start:.2f} seconds')
        return result

    return wrapper


@record_time
def download(filename):
    print(f'Start downloading {filename}.')
    time.sleep(random.random() * 6)
    print(f'{filename} download completed.')


@record_time
def upload(filename):
    print(f'Start uploading {filename}.')
    time.sleep(random.random() * 8)
    print(f'{filename} upload completed.')


download('MySQL_Full_Crash_Course.avi')
upload('Python_From_Beginner_To_Hospitalized.pdf')
```

If in some places in the code we want to remove the effect of the decorator and execute the original function directly, then we need to do a tiny bit of extra work when defining the decorator. The `wraps` function from Python's standard-library `functools` module is also a decorator. If we place it on the `wrapper` function, it helps us preserve the function as it existed before decoration. In this way, when we need to cancel the decorator, we can obtain the original function through the decorated function's `__wrapped__` attribute.

```python
import random
import time

from functools import wraps


def record_time(func):

    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f'{func.__name__} execution time: {end - start:.2f} seconds')
        return result

    return wrapper


@record_time
def download(filename):
    print(f'Start downloading {filename}.')
    time.sleep(random.random() * 6)
    print(f'{filename} download completed.')


@record_time
def upload(filename):
    print(f'Start uploading {filename}.')
    time.sleep(random.random() * 8)
    print(f'{filename} upload completed.')


download('MySQL_Full_Crash_Course.avi')
upload('Python_From_Beginner_To_Hospitalized.pdf')
download.__wrapped__('MySQL_Must_Know.pdf')
upload.__wrapped__('Python_From_Novice_To_Master.pdf')
```

### Recursion

Python allows nested function definitions, functions calling other functions, and functions calling themselves directly or indirectly. When a function calls itself, that is called **recursion**.

A classic recursive example is the factorial. The factorial of a non-negative integer `N` satisfies:

$$
N! = N \times (N-1)!
$$

That gives us a recursive implementation:

```python
def fac(num):
    if num in (0, 1):
        return 1
    return num * fac(num - 1)
```

The condition `if num in (0, 1)` is the **base case**. The expression `num * fac(num - 1)` is the recursive step.

For example, `fac(5)` unfolds like this:

```python
# 5 * fac(4)
# 5 * (4 * fac(3))
# 5 * (4 * (3 * fac(2)))
# 5 * (4 * (3 * (2 * fac(1))))
# 5 * (4 * (3 * (2 * 1)))
# 5 * (4 * (3 * 2))
# 5 * (4 * 6)
# 5 * 24
# 120
print(fac(5))  # 120
```

Note that function calls are managed through a memory structure called the **stack**, which is used to save the current execution context of the code and restore previous execution contexts after the function call ends. The stack is a last-in, first-out data structure, which means that the earliest function pushed onto the stack returns last, while the latest function pushed onto the stack returns first. Each function call adds one stack frame; each return removes one stack frame. Usually, the stack space in memory is quite small, so if recursion goes too deep, it causes stack overflow. Therefore, **recursive calls must always converge quickly**.

If we use the official Python interpreter, CPython, the default maximum stack depth for function calls is usually set to `1000`. If that depth is exceeded, the `RecursionError` mentioned above occurs. Of course, we can use the `setrecursionlimit` function from the `sys` module to change the maximum recursion depth, but this is generally not recommended. Making recursion converge quickly is what we should do; otherwise, it is better to consider iterative looping rather than recursion.

Another example is the Fibonacci sequence:

```python
def fib1(n):
    if n in (1, 2):
        return 1
    return fib1(n - 1) + fib1(n - 2)


for i in range(1, 21):
    print(fib1(i))
```

This version is simple, but inefficient because it repeats many calculations. A loop-based implementation is usually better:

```python
def fib2(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

We can also improve the recursive version with memoization using `functools.lru_cache`.

```python
from functools import lru_cache


@lru_cache()
def fib1(n):
    if n in (1, 2):
        return 1
    return fib1(n - 1) + fib1(n - 2)


for i in range(1, 51):
    print(i, fib1(i))
```

> **Tip**: `lru_cache` is a decorator with parameters, which is why it is written as `@lru_cache()` with parentheses. One of its most important parameters is `maxsize`, which controls the size of the cache.

### Summary

Decorators are a distinctive syntax feature of Python. **They allow us to enhance existing functions through decorators**, which is a very useful programming technique. On the other hand, recursive function calls can simplify some complex problems at the code level, but **recursive calls must always pay attention to the recursive rule and the convergence condition**. Only by finding the recursive rule can we use recursion, and the convergence condition ensures that the recursion can stop. Function calls save and restore execution context through the stack in memory, and the stack space is usually quite small, so **if recursion cannot converge quickly, it is very likely to cause a stack overflow error and crash the program**.
