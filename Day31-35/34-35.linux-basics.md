### A Brief History of Operating Systems

A computer system with hardware only and no software is called a "bare machine". It is difficult to use a bare machine for everyday work such as storage and computation, so special software is needed to control the hardware. The software closest to the hardware is system software, and the most important part of that is the operating system. An operating system is a collection of programs that control and manage all hardware and software resources of a computer, implement resource allocation and task scheduling, and provide interfaces and an environment for system users and other software.

#### No Operating System, Manual Operation

In the early days before operating systems existed, users first loaded a program tape or card into the computer, then started the input device to feed the program into the machine, and then used console switches to start it running. After execution finished, the printer output the result, and the user removed the tape or cards and took them away. Then the second user repeated exactly the same process. During the whole process, the user monopolized the machine, the CPU had to wait for manual operations, and resource utilization was extremely low.

#### Batch Systems

First, a supervisory program was started on the computer. Under the control of that supervisory program, the machine could automatically process one or more users' jobs in batches. After finishing one batch, the supervisor program would read another batch from the input device and store it on tape, then continue processing in the same way. The supervisor continuously handled jobs and automatically chained them together, reducing setup time and manual effort and improving resource utilization. Batch systems can be divided into single-program batch systems, multiprogram batch systems, online batch systems, and offline batch systems.

#### Time-Sharing and Real-Time Systems

A time-sharing system divides processor time into very short slices and allocates them to interactive jobs in turn. If a job cannot complete within the time slice assigned to it, that job is suspended temporarily, the processor is given to another job, and the original job waits for the next round of scheduling. Because computers are fast and jobs rotate quickly, each user feels as if they have exclusive use of the machine. Users can issue different control commands through their own terminals and complete tasks under a highly interactive human-computer environment. To address the fact that time-sharing systems could not always respond quickly enough to user instructions, real-time systems appeared. These systems are designed to complete event processing within strict time limits and respond promptly to random external events.

#### General-Purpose Operating Systems

1. In the 1960s, IBM's System/360 series had a unified operating system called OS/360.
2. In 1965, AT&T's Bell Labs joined GE and MIT in the MULTICS project.
3. In 1969, after the MULTICS project failed, Ken Thompson, while at home and wanting to play the game *Space Travel*, used assembly language to build Unics on an already outdated PDP-7.
4. In 1970 and 1971, Ken Thompson and Dennis Ritchie rewrote Unics in the B language on the PDP-11, and at Brian Kernighan's suggestion renamed it Unix.
5. In 1972 and 1973, Dennis Ritchie invented the C language to replace the less portable B language and began rewriting Unix in C.
6. In 1974, Unix released the milestone Version 5, which was almost entirely implemented in C.
7. In 1979, starting from Unix Version 7, AT&T privatized Unix through new licensing terms.
8. In 1987, Professor Andrew S. Tanenbaum created Minix, a Unix-compatible operating system developed without using any AT&T source code, so that he could teach operating-system internals without copyright disputes.
9. In 1991, while studying at the University of Helsinki, Linus Torvalds attempted to do development work on Minix. Because Minix was mainly for teaching and was not very powerful, he wrote a disk driver and file system to make reading and downloading files from the university newsgroup and mail system easier. Those pieces formed the early prototype of the Linux kernel.

### Linux Overview

Linux is a general-purpose operating system. An operating system is responsible for task scheduling, memory allocation, and handling I/O for peripheral devices. An operating system is usually composed of two parts: the kernel, which runs other programs and manages hardware such as disks and printers, and system programs, which include device drivers, low-level libraries, shells, and service programs.

The Linux kernel was developed by Linus Torvalds and released in September 1991. Linux as an operating system is a product of the internet age. It was built collaboratively by many developers around the world and is a free operating system. Note that "free" and "gratis" are not the same concept.

### Advantages of Linux

1. It is a general-purpose operating system and is not tied to a particular hardware platform.
2. It is written in C, has strong portability, and provides kernel programming interfaces.
3. It supports multiple users and multiple tasks, and it has a secure hierarchical file system.
4. It provides a large number of practical tools, complete networking support, and strong documentation.
5. It offers reliable security, good stability, and is friendlier to developers.

### Basic Commands

Linux commands usually follow the pattern below.

```bash
command [options] [target]
```

1. Get login information: `w` / `who` / `last` / `lastb`
2. See which shell you are using: `ps`

   A shell is also called a shell program. It is the interpreter between the user and the operating-system kernel, or more simply the interface for interaction between human and computer. Many Linux systems use `bash` by default, the Bourne Again SHell, because it supports tab completion for commands and paths, can preserve command history, makes environment-variable configuration convenient, and handles batch operations well.

3. View command descriptions and locations: `whatis` / `which` / `whereis`
4. Clear the screen: `clear`
5. View help documents: `man` / `info` / `--help` / `apropos`
6. View system and host information: `uname` / `hostname`
7. View time and date: `date` / `cal`
8. Reboot and shut down: `reboot` / `shutdown`
9. Exit the current login session: `exit` / `logout`
10. View command history: `history`

### Utility Programs

#### File and Directory Operations

1. Create and remove empty directories: `mkdir` / `rmdir`
2. Create and delete files: `touch` / `rm`

   - `touch` creates empty files or updates file times. In Linux, files have three relevant times:
     - content modification time, `mtime`
     - metadata change time, `ctime`
     - last access time, `atime`
   - Important `rm` options:
     - `-i`: interactive deletion, asking for confirmation on each item
     - `-r`: recursive deletion of directories and their contents
     - `-f`: force deletion, ignoring nonexistent files and suppressing prompts

3. Change and view the current working directory: `cd` / `pwd`

   > **Note**: `cd` can take either a relative path, interpreted from the current location, or an absolute path beginning with `/`. `cd ..` moves back one level.

4. View directory contents: `ls`

   - `-l`: long format
   - `-a`: show dotfiles and dot-directories
   - `-R`: recursively expand directories
   - `-d`: list only directories
   - `-S` / `-t`: sort by size or time

5. View file contents: `cat` / `tac` / `head` / `tail` / `more` / `less` / `rev` / `od`

   > **Note**: The `wget` command often appears in examples here as a network download tool that retrieves resources from a URL.

6. Copy and move files: `cp` / `mv`
7. Rename files: `rename`
8. Find files and search content: `find` / `grep`

   > **Note**: `grep` can search with regular expressions. If you need regex matching, use `grep -E` or `egrep`.

9. Create and inspect links: `ln` / `readlink`

   > **Note**: Links are divided into hard links and soft links, also called symbolic links. A hard link can be thought of as a pointer to file data, somewhat like reference counting in Python. Each additional hard link increases the file's link count by 1, and only when the count drops to 0 can the file's storage space be reused. When we delete a file in normal everyday work, we are usually deleting only a pointer, not immediately wiping the underlying data. A symbolic link behaves more like a shortcut in Windows. When the file it points to is removed, the symbolic link stops working.

10. Compress and decompress: `gzip` / `gunzip` / `xz`
11. Archive and extract archives: `tar`

   > **Note**: Both creating and extracting archives use the `tar` command. Creating an archive usually uses `-cvf`, where `c` means create, `v` means verbose, and `f` specifies the archive file. Extracting usually uses `-xvf`, where `x` means extract.

12. Turn standard input into command-line arguments: `xargs`

   This command is often used together with pipes and redirection.

13. Show the file name or directory name part of a path: `basename` / `dirname`
14. Other related tools:

   - `sort`: sort content
   - `uniq`: remove adjacent duplicates
   - `tr`: replace specified content with new content
   - `cut` / `paste`: cut and paste content columns
   - `split`: split files
   - `file`: determine file type
   - `wc`: count lines, words, and bytes
   - `iconv`: convert encodings

#### Pipes and Redirection

1. Using a pipe, `|`

   Example: count the number of files under the current directory.

   ```bash
   find ./ | wc -l
   ```

   Example: list files and directories under the current path and add a number to each item.

   ```bash
   ls | cat -n
   ```

   Example: count records in `record.log` that contain `AAA` but do not contain `BBB`.

   ```bash
   cat record.log | grep AAA | grep -v BBB | wc -l
   ```

2. Output and error redirection: `>` / `>>` / `2>`
3. Input redirection: `<`
4. Multiple redirection: `tee`

   The following command both shows the result of `ls` on the terminal and appends it to `ls.txt`.

   ```bash
   ls | tee -a ls.txt
   ```

#### Aliases

1. `alias`
2. `unalias`

Aliases are convenient for mapping commonly used command combinations to short names.

#### Text Processing

1. Stream editor: `sed`

   `sed` is a tool for operating on, filtering, and transforming text. It can append lines, insert lines, delete lines, and do substitutions. Like many commands shown earlier, it does not modify the original file unless you explicitly redirect or save the result.

2. Pattern scanning and processing language: `awk`

   `awk` is both a programming language and one of the most powerful text-processing tools in Linux. It can extract specific columns from text, use regular expressions to retrieve content, display specified rows, and perform statistics and calculations. In short, it is extremely powerful.

### User Management

1. Create and delete users: `useradd` / `userdel`

   - `-d`: specify the user's home directory when creating a user
   - `-g`: specify the user's primary group when creating a user

2. Create and delete user groups: `groupadd` / `groupdel`

   > **Note**: User groups mainly exist to make it easier to manage a set of users together.

3. Change passwords: `passwd`

   > **Note**: If `passwd` is used without specifying a target, it changes the current user's password. If you need to modify many users' passwords in bulk, you can use `chpasswd`.

   - `-l` / `-u`: lock or unlock a user
   - `-d`: clear a user's password
   - `-e`: force the password to expire immediately, so the user must change it at login
   - `-i`: disable the user some number of days after password expiration

4. View and modify password validity periods: `chage`
5. Switch users: `su`
6. Execute commands as an administrator: `sudo`

   > **Note**: If a user is expected to run commands with administrator privileges, that user must appear in the `sudoers` list. The `sudoers` file lives under `/etc`.

7. Edit the `sudoers` file: `visudo`
8. Display user and group information: `id`
9. Send messages to other users: `write` / `wall`
10. View or set whether you accept messages from other users: `mesg`

### File System

#### Files and Paths

1. Naming rules: the maximum file-name length depends on the file-system type, but generally a file name should not exceed 255 characters. Although most characters can be used in file names, it is best to stick to upper- and lower-case English letters, digits, underscores, and periods. File names can contain spaces, but it is better to avoid them, because then you need either quotes or escaping.
2. Extensions: file extensions are optional in Linux, but they help us understand file contents. Some applications recognize files by their extensions, but many do not. Commands such as `file` do not rely on extensions.
3. Hidden files: files whose names begin with a dot are hidden files in Linux.

#### Directory Structure

1. `/bin` - binary files for basic commands
2. `/boot` - static files for the boot loader
3. `/dev` - device files
4. `/etc` - configuration files
5. `/home` - parent directory for ordinary users' home directories
6. `/lib` - shared library files
7. `/lib64` - shared 64-bit library files
8. `/lost+found` - stores unlinked files
9. `/media` - mount points for automatically detected devices
10. `/mnt` - temporary mount points
11. `/opt` - installation location for optional add-on packages
12. `/proc` - kernel and process information
13. `/root` - the home directory of the superuser
14. `/run` - runtime data required by the system
15. `/sbin` - binaries for the superuser
16. `/sys` - a pseudo file system for devices
17. `/tmp` - temporary files
18. `/usr` - user applications
19. `/var` - variable data

#### Access Permissions

1. `chmod` - change file mode bits

   > **Note**: `chmod` can change permissions in two ways: symbolic notation and numeric notation. Besides `chmod`, `umask` can be used to specify which permission bits will be removed from the default permissions of new files.

2. `chown` - change file owner
3. `chgrp` - change group ownership

#### Disk Management

1. List file-system disk-usage status: `df`
2. Disk partition-table operations: `fdisk`
3. Disk partitioning tool: `parted`
4. Format a file system: `mkfs`
5. File-system checking: `fsck`
6. Convert or copy files: `dd`
7. Mount and unmount: `mount` / `umount`
8. Create, activate, and disable swap partitions: `mkswap` / `swapon` / `swapoff`

> **Note**: Running the commands above carries some risk. If you do not understand them clearly, do not use them casually. When using them, it is best to follow reference materials carefully and confirm whether you really intend to perform the operation.

### Editor: `vim`

1. Start `vim`. You can launch it with either `vi` or `vim`. A file name can be specified at launch, or you can name the file when saving.
2. Command mode, insert mode, and last-line mode. `vim` starts in command mode. Pressing `i` enters insert mode. Pressing `Esc` returns to command mode. Entering `:` from command mode enters last-line mode, where `q!` forces quit without saving. In command mode, `v` enters visual mode, where a region can be selected and operated on.
3. Save and quit: `:wq`, `q!`, `ZZ`, `:w`
4. Cursor operations
   - `h`, `j`, `k`, `l`
   - `Ctrl+y`, `Ctrl+e`
   - `Ctrl+f`, `Ctrl+b`
   - `G`, `gg`, and numeric line jumps
5. Text operations
   - delete: `dd`, `d$`, `d0`, `dw`, `:%d`
   - copy and paste: `yy`, `p`
   - undo and redo: `u`, `Ctrl+r`
   - sort content: `%!sort`
6. Search and replace
   - searching with `/`
   - replacing with commands such as `:1,$s/doc.*/hello/gice`
7. Settings in last-line mode
   - `set ts=4`
   - `set nu` / `set nonu`
   - `syntax on` / `syntax off`
   - `set ruler`
   - `set hls` / `set nohls`

   > **Note**: If you want these settings to take effect every time `vim` starts, write them to `.vimrc` in the user's home directory.

8. Advanced tricks
   - compare multiple files: `vim -d foo.txt bar.txt`
   - open multiple files
   - split windows with `sp` or `vs`
   - map shortcut keys with `map` or `inoremap`
   - record and replay macros with `q`, registers, and `@`

### Configuring Services

Under Linux we can install and configure many kinds of services, turning the system into a database server, web server, cache server, file server, message-queue server, and so on. Most Linux services are configured as daemons, background processes that continue to run without preventing Linux from shutting down cleanly. That is why many service names end with the letter `d`, short for `daemon`, such as `firewalld`, `mysqld`, and `httpd`. After a service is installed, it can usually be started, stopped, and otherwise managed with `systemctl` or `service`.

Examples from the lesson:

1. Start the firewall service: `systemctl start firewalld`
2. Stop the firewall service: `systemctl stop firewalld`
3. Restart the firewall service: `systemctl restart firewalld`
4. View firewall status: `systemctl status firewalld`
5. Enable or disable the firewall at boot: `systemctl enable firewalld` / `systemctl disable firewalld`

### Shell Programming

As mentioned earlier, the shell is the application that connects the user and the operating system. It provides the interface for human-computer interaction. Shell scripts are programs written for the shell. We can use them for system management and file operations. In short, writing shell scripts is a basic skill for anyone who uses Linux seriously.

The internet contains a great deal of shell-scripting material, so this lesson does not attempt a complete treatment. Instead, it gives several small examples:
