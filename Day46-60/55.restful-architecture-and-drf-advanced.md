## RESTful Architecture and DRF Advanced Topics

Besides function-based views, DRF can also build REST APIs with class-based views. The class-based approach is concise and productive, although function-based views remain more flexible when you need highly customized behavior.

### Using CBV

#### Inheriting from subclasses of `APIView`

`ListAPIView` is a subclass of `APIView`. It handles GET requests for list data and already implements the logic needed to return a resource collection.

#### `ListAPIView`

You can implement a read-only subject list by inheriting from `ListAPIView`:

```python
from rest_framework.generics import ListAPIView


class SubjectView(ListAPIView):
    queryset = Subject.objects.all()
    serializer_class = SubjectSerializer
```

Then map it in `urls.py`:

```python
urlpatterns = [
    path('api/subjects/', SubjectView.as_view()),
]
```

#### `ModelViewSet`

If the resource should support the full CRUD set, `ModelViewSet` is even simpler:

```python
from rest_framework.viewsets import ModelViewSet


class SubjectViewSet(ModelViewSet):
    queryset = Subject.objects.all()
    serializer_class = SubjectSerializer
```

`ModelViewSet` combines support for:

- create
- retrieve
- update
- partial update
- destroy
- list

You can confirm from the source that it combines a set of mixins that implement create, retrieve, update, destroy, and list behavior. To register it, use a router:

```python
from rest_framework.routers import DefaultRouter

router = DefaultRouter()
router.register('api/subjects', SubjectViewSet)
urlpatterns += router.urls
```

For read-only APIs, DRF also provides `ReadOnlyModelViewSet`, which supports only GET requests for a single resource or a resource list.

### Pagination

Large list endpoints should usually paginate rather than loading everything at once.

Global DRF pagination configuration:

```python
REST_FRAMEWORK = {
    'PAGE_SIZE': 10,
    'DEFAULT_PAGINATION_CLASS': 'rest_framework.pagination.PageNumberPagination'
}
```

DRF also provides:

- `LimitOffsetPagination`
- `CursorPagination`

Custom paginator:

```python
from rest_framework.pagination import PageNumberPagination


class CustomizedPagination(PageNumberPagination):
    page_size = 5
    page_size_query_param = 'size'
    max_page_size = 50
```

Use it in the view:

```python
class SubjectView(ListAPIView):
    queryset = Subject.objects.all()
    serializer_class = SubjectSerializer
    pagination_class = CustomizedPagination
```

If you do not want pagination, set `pagination_class = None`.

### Filtering

To filter teachers by subject in a CBV, override `get_queryset`:

```python
class TeacherView(ListAPIView):
    serializer_class = TeacherSerializer

    def get_queryset(self):
        queryset = Teacher.objects.defer('subject')
        try:
            sno = self.request.GET.get('sno', '')
            queryset = queryset.filter(subject__no=sno)
            return queryset
        except ValueError:
            raise Http404('No teachers found.')
```

The original lesson also mentions that `django-filter` can be combined with DRF to support more systematic filtering using `DjangoFilterBackend`. After configuring the filter backend, you can use `filter_fields` or `filterset_class` to describe how filtering should work.
