## Logging and the Debug Toolbar

### Configuring Logging

During development, detailed debug output helps you diagnose problems. After deployment, warning and error logs help operators understand system health and support maintenance work. Log data is also valuable for traffic analysis and product analytics.

Django logging is configured in `settings.py`. A common configuration includes:

- formatters
- filters
- handlers
- loggers

Example:

```python
LOGGING = {
    'version': 1,
    'disable_existing_loggers': False,
    'formatters': {
        'simple': {
            'format': '%(asctime)s %(module)s.%(funcName)s: %(message)s',
            'datefmt': '%Y-%m-%d %H:%M:%S',
        },
        'verbose': {
            'format': '%(asctime)s %(levelname)s [%(process)d-%(threadName)s] '
                      '%(module)s.%(funcName)s line %(lineno)d: %(message)s',
            'datefmt': '%Y-%m-%d %H:%M:%S',
        }
    },
    'filters': {
        'require_debug_true': {
            '()': 'django.utils.log.RequireDebugTrue',
        },
    },
    'handlers': {
        'console': {
            'class': 'logging.StreamHandler',
            'level': 'DEBUG',
            'filters': ['require_debug_true'],
            'formatter': 'simple',
        },
        'file1': {
            'class': 'logging.handlers.TimedRotatingFileHandler',
            'filename': 'access.log',
            'when': 'W0',
            'backupCount': 12,
            'formatter': 'simple',
            'level': 'INFO',
        },
        'file2': {
            'class': 'logging.handlers.TimedRotatingFileHandler',
            'filename': 'error.log',
            'when': 'D',
            'backupCount': 31,
            'formatter': 'verbose',
            'level': 'WARNING',
        },
    },
    'loggers': {
        'django': {
            'handlers': ['console', 'file1', 'file2'],
            'propagate': True,
            'level': 'DEBUG',
        },
    }
}
```

Important format placeholders include:

- `%(name)s`
- `%(levelname)s`
- `%(filename)s`
- `%(funcName)s`
- `%(module)s`
- `%(lineno)s`
- `%(asctime)s`
- `%(thread)d`
- `%(threadName)s`
- `%(process)d`

Common handlers include:

- `StreamHandler`
- `FileHandler`
- `TimedRotatingFileHandler`
- `RotatingFileHandler`
- `HTTPHandler`
- `SocketHandler`
- `SMTPHandler`
- `MemoryHandler`

Python logging levels from low to high:

- `NOTSET`
- `DEBUG`
- `INFO`
- `WARNING`
- `ERROR`
- `CRITICAL`

Useful built-in Django loggers:

- `django`
- `django.request`
- `django.server`
- `django.template`
- `django.db.backends`

`django.db.backends` is especially useful when you want to inspect SQL generated by the ORM.

### Django Debug Toolbar

`django-debug-toolbar` is one of the most useful tools for debugging and optimizing Django projects during development.

It can show:

- Django version
- request timing
- settings
- request and response headers
- request variables
- static file loading
- template details
- cache usage
- signals
- logging output
- SQL statements and execution time

Install it:

```bash
pip install django-debug-toolbar
```

Configure `settings.py`:

```python
INSTALLED_APPS = [
    'debug_toolbar',
]

MIDDLEWARE = [
    'debug_toolbar.middleware.DebugToolbarMiddleware',
]

DEBUG_TOOLBAR_CONFIG = {
    'JQUERY_URL': 'https://cdn.bootcss.com/jquery/3.3.1/jquery.min.js',
    'SHOW_COLLAPSED': True,
    'SHOW_TOOLBAR_CALLBACK': lambda x: True,
}
```

Configure `urls.py`:

```python
if settings.DEBUG:
    import debug_toolbar
    urlpatterns.insert(0, path('__debug__/', include(debug_toolbar.urls)))
```

### ORM Optimization

Once logging or the debug toolbar is enabled, it becomes easy to spot ORM inefficiencies.

For example, `Teacher.objects.all()` may trigger an N+1 query problem when each teacher’s related subject is fetched separately.

A better version is:

```python
queryset = Teacher.objects.all().select_related('subject')
```

If you only need certain columns:

```python
queryset = Teacher.objects.all().only('name', 'good_count', 'bad_count')
```

Aggregation is also supported:

```python
queryset = Teacher.objects.values('subject').annotate(good=Avg('good_count'), bad=Avg('bad_count'))
```

or with subject names:

```python
queryset = Teacher.objects.values('subject__name').annotate(good=Avg('good_count'), bad=Avg('bad_count'))
```

This is one of Django ORM’s strengths: you can express grouping and aggregation in object-oriented code while still generating SQL behind the scenes.
