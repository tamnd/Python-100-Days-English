## A Deeper Look at Models

In the previous lesson we mentioned that Django is built around an MVC-like architecture. In practice, the "model" part means data and the rules around that data. In most real systems, relational databases are still the default persistence solution, so this lesson uses a simple voting project to explain Django models and ORM usage.

The sample project works like this:

- the home page shows all subjects on an online education platform
- clicking a subject displays its teachers
- logged-in users can vote for or against a teacher
- unregistered users can sign up
- login and registration pages are also part of the project

MySQL is used as the backing database.

### Create the Project and App

Create a Django project named `vote`, add a virtual environment and dependencies, then create an app named `polls` and a `templates` directory for template files.

Static pages prepared for the project include:

- `subjects.html`
- `teachers.html`
- `login.html`
- `register.html`

These pages are later turned into Django templates.

### Configure MySQL

1. Create the database, a user, and grant privileges:

```SQL
create database vote default charset utf8;
create user 'hellokitty'@'%' identified by 'Hellokitty.618';
grant all privileges on vote.* to 'hellokitty'@'%';
flush privileges;
```

2. Create the subject and teacher tables:

```SQL
use vote;

create table `tb_subject`
(
    `no` integer auto_increment comment 'Subject ID',
    `name` varchar(50) not null comment 'Subject name',
    `intro` varchar(1000) not null default '' comment 'Subject introduction',
    `is_hot` boolean not null default 0 comment 'Whether it is a popular subject',
    primary key (`no`)
);

create table `tb_teacher`
(
    `no` integer auto_increment comment 'Teacher ID',
    `name` varchar(20) not null comment 'Teacher name',
    `sex` boolean not null default 1 comment 'Gender',
    `birth` date not null comment 'Date of birth',
    `intro` varchar(1000) not null default '' comment 'Introduction',
    `photo` varchar(255) not null default '' comment 'Photo',
    `gcount` integer not null default 0 comment 'Positive votes',
    `bcount` integer not null default 0 comment 'Negative votes',
    `sno` integer not null comment 'Subject ID',
    primary key (`no`),
    foreign key (`sno`) references `tb_subject` (`no`)
);
```

3. Install MySQL database support for Django:

```bash
pip install mysqlclient
```

If `mysqlclient` cannot be installed, `pymysql` can be used as a fallback, but it requires extra compatibility handling and is generally less convenient in Django projects.

### Reverse Engineering Models

Django provides an ORM, or Object-Relational Mapping layer. Python code uses objects, while relational databases use tables. ORM bridges the two worlds.

You can generate model classes from existing tables with:

```bash
python manage.py inspectdb > polls/models.py
```

After cleanup, the models might look like this:

```python
from django.db import models


class Subject(models.Model):
    no = models.AutoField(primary_key=True, verbose_name='ID')
    name = models.CharField(max_length=50, verbose_name='Name')
    intro = models.CharField(max_length=1000, verbose_name='Introduction')
    is_hot = models.BooleanField(verbose_name='Is Popular')

    class Meta:
        managed = False
        db_table = 'tb_subject'


class Teacher(models.Model):
    no = models.AutoField(primary_key=True, verbose_name='ID')
    name = models.CharField(max_length=20, verbose_name='Name')
    sex = models.BooleanField(default=True, verbose_name='Gender')
    birth = models.DateField(verbose_name='Date of Birth')
    intro = models.CharField(max_length=1000, verbose_name='Introduction')
    photo = models.ImageField(max_length=255, verbose_name='Photo')
    good_count = models.IntegerField(default=0, db_column='gcount', verbose_name='Positive Votes')
    bad_count = models.IntegerField(default=0, db_column='bcount', verbose_name='Negative Votes')
    subject = models.ForeignKey(Subject, models.DO_NOTHING, db_column='sno')

    class Meta:
        managed = False
        db_table = 'tb_teacher'
```

Model classes map to tables, model instances map to rows, and model attributes map to columns.

### CRUD with the ORM

Open a Django shell:

```bash
python manage.py shell
```

Create:

```python
from polls.models import Subject

subject1 = Subject(name='Python Full-Stack Development', intro='A very popular subject', is_hot=True)
subject1.save()
subject2 = Subject(name='Full-Stack Software Testing', intro='A subject about automated testing', is_hot=False)
subject2.save()
subject3 = Subject(name='JavaEE Distributed Development', intro='Server-side development based on Java', is_hot=True)
subject3.save()
```

Delete:

```python
subject = Subject.objects.get(no=2)
subject.delete()
```

Update:

```python
subject = Subject.objects.get(no=1)
subject.name = 'Python and AI'
subject.save()
```

Query:

```python
Subject.objects.all()
Subject.objects.filter(is_hot=True)
Subject.objects.get(no=1)
```

Django’s ORM also supports ordering, filtering, aggregation, joining related objects, and much more. In practice, most CRUD work in a Django application is written at the model layer through these APIs instead of raw SQL.

For multiple-object queries, Django returns a `QuerySet`. `QuerySet` uses lazy querying, which means creating the `QuerySet` itself does not immediately trigger database activity. Django only sends the SQL and fetches the results when the queryset is actually evaluated. This is something you need to keep in mind in real development.

If you want to update multiple rows, you do not have to fetch model objects one by one and modify their attributes individually. You can use the `update()` method on a `QuerySet` to update multiple rows at once.

### Managing Models with Django Admin

After creating model classes, you can manage them through Django's built-in admin application. In real-world projects, the admin site may not fully satisfy your needs, but while learning Django it is a very useful tool and it also gives you a sense of what a management backend typically needs to provide.

1. Migrate the tables needed by the `admin` application.

```bash
python manage.py migrate
```

2. Create a superuser account for the admin site. You will be prompted for a username, email, and password.

```bash
python manage.py createsuperuser
```

> **Note**: When entering the password, there is no terminal echo and you cannot backspace in the usual visible way, so type carefully.

3. Run the project and visit `http://127.0.0.1:8000/admin` in a browser. Log in with the superuser account you just created.

4. Register the model classes in `polls/admin.py`.

```python
from django.contrib import admin

from polls.models import Subject, Teacher

admin.site.register(Subject)
admin.site.register(Teacher)
```

After registering the models, they will appear in the admin site and can be created, viewed, updated, and deleted there.

5. Register model admin classes so the data is displayed in a more useful way.

```python
from django.contrib import admin

from polls.models import Subject, Teacher


class SubjectModelAdmin(admin.ModelAdmin):
    list_display = ('no', 'name', 'intro', 'is_hot')
    search_fields = ('name', )
    ordering = ('no', )


class TeacherModelAdmin(admin.ModelAdmin):
    list_display = ('no', 'name', 'sex', 'birth', 'good_count', 'bad_count', 'subject')
    search_fields = ('name', )
    ordering = ('no', )


admin.site.register(Subject, SubjectModelAdmin)
admin.site.register(Teacher, TeacherModelAdmin)
```

To make the model output more readable, you can also add a `__str__` magic method to `Subject` and return the subject name from it. That way, places that would otherwise display something like `Subject object(1)` can display the actual subject name instead.

### Implement the Subject and Teacher Pages

1. Modify `polls/views.py` and write view functions to render the subject page and teacher page.

```python
from django.shortcuts import render, redirect

from polls.models import Subject, Teacher


def show_subjects(request):
    subjects = Subject.objects.all().order_by('no')
    return render(request, 'subjects.html', {'subjects': subjects})


def show_teachers(request):
    try:
        sno = int(request.GET.get('sno'))
        teachers = []
        if sno:
            subject = Subject.objects.only('name').get(no=sno)
            teachers = Teacher.objects.filter(subject=subject).order_by('no')
        return render(request, 'teachers.html', {
            'subject': subject,
            'teachers': teachers
        })
    except (ValueError, Subject.DoesNotExist):
        return redirect('/')
```
