### Views

A view is a virtual table created from a stored query. It does not store data itself; instead, it stores SQL logic and presents the result like a table.

Benefits of views:

1. They can hide the underlying table structure and expose only the fields the outside world needs.
2. In most cases they are read-only, which reduces the chance of direct accidental updates.
3. They let you reuse complex SQL statements.
4. They can reshape or format data differently from the physical table.

Create a simple view:

```SQL
create view `vw_emp_simple`
as
select  `eno`,
        `ename`,
        `job`,
        `dno`
  from  `tb_emp`;
```

Query the view:

```SQL
select * from `vw_emp_simple`;
```

Because the view hides salary and allowance fields, it can be useful when combined with permission control.

Not every view is updatable. The following types are generally not updatable:

1. Views using aggregate functions, `distinct`, `group by`, `having`, `union`, or `union all`.
2. Views whose `select` clause contains subqueries.
3. Views built on top of other non-updatable views.
4. Views whose `where` clause contains subqueries referencing tables in the `from` clause.

Drop a view:

```SQL
drop view if exists `vw_emp_simple`;
```

You can also update a definition by using `create or replace view`.

Rules and limitations:

1. Views can be nested and joined with tables.
2. A view may contain `order by`, but an outer `order by` can override it.
3. Views do not have their own indexes, and they do not trigger indexes or caching behavior like physical tables.

### Functions

MySQL functions are conceptually similar to Python functions: they package reusable logic. One difference is that MySQL functions can also work with SQL expressions and, depending on the declaration, may read data.

The following function truncates a long string:

```SQL
delimiter $$

create function fn_truncate_string(
    content varchar(10000),
    max_length int unsigned
) returns varchar(10000) no sql
begin
    declare result varchar(10000) default content;
    if char_length(content) > max_length then
        set result = left(content, max_length);
        set result = concat(result, '……');
    end if;
    return result;
end $$

delimiter ;
```

Notes:

- `no sql` means the function body does not execute SQL statements.
- If the function reads data, you would typically declare it as `reads sql data`.
- `delimiter` is changed because the function body itself contains semicolons.

Call the function in a query:

```SQL
select fn_truncate_string('Walk with me through the streets of Chengdu until all the lights go out and we still do not stop', 10) as short_string;
```

### Procedures

A stored procedure is a precompiled collection of SQL statements stored in the database. Procedures can simplify application development, reduce client-server communication, and help encapsulate multi-step business operations.

Example: when an e-commerce system processes an order, it may need to:

1. Check whether inventory exists and whether it is sufficient.
2. Lock inventory and decrement available stock.
3. If stock is insufficient, contact suppliers or generate warning records.
4. Write logs and create user notifications regardless of success or failure.

Procedures help group this logic together.

The following procedure performs a salary increase in the `hrs` database:

- Department `10`: add `300`
- Department `20`: add `800`
- Department `30`: add `500`

```SQL
delimiter $$

create procedure sp_upgrade_salary()
begin
    declare flag boolean default 1;
    declare continue handler for sqlexception set flag=0;

    start transaction;
    
    update tb_emp set sal=sal+300 where dno=10;
    update tb_emp set sal=sal+800 where dno=20;
    update tb_emp set sal=sal+500 where dno=30;

    if flag then
        commit;
    else
        rollback;
    end if;
end $$

delimiter ;
```

The procedure defines:

- a `flag` variable
- an exception handler
- a transaction block using `start transaction`
- commit or rollback logic depending on whether an error occurred

Call the procedure:

```SQL
call sp_upgrade_salary();
```

Drop the procedure:

```SQL
drop procedure if exists sp_upgrade_salary;
```

Although procedures can be useful, pushing too much business logic and too many heavy computations into the database can overload the database server. In modern internet applications, it is usually better to let the database focus on storage while the application server handles most complex logic.

### Additional Topics

#### Normal Forms

Normal form theory provides guidance for relational schema design.

1. First Normal Form: every column value must be atomic.
2. Second Normal Form: every non-key attribute must fully depend on the key.
3. Third Normal Form: non-key attributes should depend only on candidate keys, not on each other.

> **Note**: In practice, some denormalization is often introduced intentionally for performance reasons.

#### Data Integrity

1. Entity integrity: each entity is unique.
   - `primary key`
   - `unique`
2. Referential integrity: relationships cannot reference nonexistent rows.
   - `foreign key`
3. Domain integrity: data must be valid.
   - proper data type and length
   - `not null`
   - `default`
