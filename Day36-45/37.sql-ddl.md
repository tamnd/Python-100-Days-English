## DDL in Detail

We usually divide SQL into four categories: DDL, Data Definition Language; DML, Data Manipulation Language; DCL, Data Control Language; and TCL, Transaction Control Language. DDL is mainly used to create, delete, and modify objects in a database, such as creating, deleting, and modifying two-dimensional tables. Its core keywords include `create`, `drop`, and `alter`. DML is mainly responsible for inserting, deleting, updating, and querying data, using keywords such as `insert`, `delete`, `update`, and `select`. DCL is used to grant and revoke privileges, with `grant` and `revoke` as the core keywords. TCL is usually used for transaction control.

> **Note**: SQL is case-insensitive. In general, we recommend writing keywords in uppercase and the remaining parts in lowercase. If your company has a mandatory SQL style guide, follow it. Personal preference should not override company coding standards.

### Creating Databases and Tables

Next, let us build a very simple database for a school course-selection system. We will name the database `school`. The four key entities are colleges, teachers, students, and courses. Students belong to colleges, and that relationship is many-to-one, because one college can have many students, but a student normally belongs to only one college. Similarly, teachers also belong to colleges in a many-to-one relationship. A teacher can teach many courses. If each course has only one instructor, then courses and teachers are also in a many-to-one relationship. If multiple teachers were allowed to teach a single course together, then the relationship would become many-to-many. To keep things simple, we will model courses and teachers as many-to-one. Students and courses form a typical many-to-many relationship, because one student can choose many courses and one course can be chosen by many students. In a relational database, a many-to-many relationship must be maintained through an intermediate table. In the end, our school course-selection system will have five tables: `tb_college`, `tb_student`, `tb_teacher`, `tb_course`, and `tb_record`, where `tb_record` is the middle table used to maintain the many-to-many relationship between students and courses.

```sql
-- Drop the database named school if it already exists
DROP DATABASE IF EXISTS `school`;

-- Create the database named school and set the default character set and collation
CREATE DATABASE `school` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

-- Switch into the school database context
USE `school`;

-- Create the college table
CREATE TABLE `tb_college`
(
`col_id`    int unsigned AUTO_INCREMENT      COMMENT 'ID',
`col_name`  varchar(50)  NOT NULL            COMMENT 'Name',
`col_intro` varchar(500) NOT NULL DEFAULT '' COMMENT 'Introduction',
PRIMARY KEY (`col_id`)
);

-- Create the student table
CREATE TABLE `tb_student`
(
`stu_id`    int unsigned NOT NULL           COMMENT 'Student ID',
`stu_name`  varchar(20)  NOT NULL           COMMENT 'Name',
`stu_sex`   boolean      NOT NULL DEFAULT 1 COMMENT 'Sex',
`stu_birth` date         NOT NULL           COMMENT 'Birth date',
`stu_addr`  varchar(255) DEFAULT ''         COMMENT 'Hometown',
`col_id`    int unsigned NOT NULL           COMMENT 'College',
PRIMARY KEY (`stu_id`),
CONSTRAINT `fk_student_col_id` FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`)
);

-- Create the teacher table
CREATE TABLE `tb_teacher`
(
`tea_id`    int unsigned NOT NULL                COMMENT 'Employee ID',
`tea_name`  varchar(20)  NOT NULL                COMMENT 'Name',
`tea_title` varchar(10)  NOT NULL DEFAULT 'TA'   COMMENT 'Title',
`col_id`    int unsigned NOT NULL                COMMENT 'College',
PRIMARY KEY (`tea_id`),
CONSTRAINT `fk_teacher_col_id` FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`)
);

-- Create the course table
CREATE TABLE `tb_course`
(
`cou_id`     int unsigned NOT NULL COMMENT 'ID',
`cou_name`   varchar(50)  NOT NULL COMMENT 'Name',
`cou_credit` int          NOT NULL COMMENT 'Credits',
`tea_id`     int unsigned NOT NULL COMMENT 'Instructor',
PRIMARY KEY (`cou_id`),
CONSTRAINT `fk_course_tea_id` FOREIGN KEY (`tea_id`) REFERENCES `tb_teacher` (`tea_id`)
);

-- Create the course selection record table
CREATE TABLE `tb_record`
(
`rec_id`   bigint unsigned AUTO_INCREMENT COMMENT 'Selection record ID',
`stu_id`   int unsigned    NOT NULL       COMMENT 'Student ID',
`cou_id`   int unsigned    NOT NULL       COMMENT 'Course ID',
`sel_date` date            NOT NULL       COMMENT 'Selection date',
`score`    decimal(4,1)                   COMMENT 'Exam score',
PRIMARY KEY (`rec_id`),
CONSTRAINT `fk_record_stu_id` FOREIGN KEY (`stu_id`) REFERENCES `tb_student` (`stu_id`),
CONSTRAINT `fk_record_cou_id` FOREIGN KEY (`cou_id`) REFERENCES `tb_course` (`cou_id`),
CONSTRAINT `uk_record_stu_cou` UNIQUE (`stu_id`, `cou_id`)
);
```

Several points in the DDL above are worth emphasizing:

- First, in the SQL above, database names, table names, and column names are all wrapped in backticks. Backticks are not required, but they solve conflicts between identifiers and SQL keywords, that is, words with special meaning in SQL.

- When creating the database, we used `default character set utf8mb4` to specify that the default character set should be `utf8mb4`, which means UTF-8 with up to four bytes per character. We recommend this character set, and it is also the default in MySQL 8.x, because it supports international characters and can store Emoji. You can use the command below to view the character sets supported by MySQL and their default collations.

  ```sql
  show character set;
  ```

- If you want MySQL to use a default character set when the service starts, you can modify the MySQL configuration and add the following content.

  ```ini
  [mysqld]
  character-set-server=utf8
  ```

  > **Tip**: If you are not sure how to modify MySQL's configuration file, you can leave this alone for now.

- When creating and deleting databases, the keyword `database` can also be replaced with `schema`; the two mean the same thing here.

- In the table definitions, `not null` is a non-null constraint, meaning the column cannot be empty. `default` is used to assign a default value to a column, so we call it a default-value constraint. `primary key` is the primary-key constraint, meaning the column uniquely identifies each record and ensures that every record is unique because primary-key values cannot be duplicated. `foreign key` is the foreign-key constraint, which maintains referential integrity between two tables. For example, because the `col_id` column in the student table has a foreign-key constraint and must `references` the `col_id` column in the college table, the college number in the student table must come from an existing college number in the college table and cannot be assigned arbitrarily. If you want to give names to primary-key or foreign-key constraints, you can use the `constraint` keyword followed by the constraint name.

- The `comment` keyword in the table definition is used to add comments to columns and tables, improving readability and maintainability.

- When creating tables, we can choose the underlying storage engine. MySQL supports multiple storage engines, which can be viewed with `show engines`. In versions after MySQL 5.5, the default storage engine is InnoDB, which is also the one we recommend, because it is better suited to modern internet applications with high concurrency, strong performance requirements, and the need for transaction support. For backward compatibility of SQL statements, we can explicitly specify `engine=innodb` after the closing parenthesis of the `create table` statement.

  ```sql
  show engines\G
  ```

  > **Note**: The `\G` above changes the output style. In the command-line client, if a table has many columns and the output is too wide for one line, the normal layout becomes hard to read. Using `\G` displays each column of a record on its own line, which is much more comfortable in the command-line client.

- From comparisons of MySQL storage engines, we can see that InnoDB is the only one that supports foreign keys, transactions, and row-level locking, which is why we said it is better suited to internet applications. In newer MySQL versions, it is also the default engine.

- When choosing column data types while defining table structure, if you are unsure which type is most appropriate, you can use MySQL's help system to understand each type's characteristics, length, precision, and related information.

  ```sql
  ? data types
  ```

  > **Note**: In MySQL Workbench, `?` cannot be used to get help. You need to use the `help` command instead.

### Summary

DDL is used to define the structure of a database. Through DDL, we can create databases, create tables, define constraints, and select storage engines. For relational databases, good table structure design is an important part of later development and maintenance.
