## New Features in MySQL

### JSON Type

When developers use relational databases for persistence, they often feel constrained by strictly structured tables because every column and type must be designed in advance. As the business evolves, schema changes can become painful.

Starting with MySQL 5.7, MySQL added support for the `JSON` type. MySQL 8.0 further improved JSON performance, especially around logging. Used well, JSON gives relational databases some of the flexibility people usually associate with NoSQL systems.

JSON data commonly appears in two forms:

1. JSON object

```JSON
{"name": "Luo Hao", "tel": "13122335566", "QQ": "957658"}
```

2. JSON array

```JSON
[1, 2, 3]
```

```JSON
[{"name": "Luo Hao", "tel": "13122335566"}, {"name": "Wang Dachui", "QQ": "123456"}]
```

A common use case is flexible login information. A product may allow phone login, WeChat login, QQ login, Weibo login, and more, but users rarely provide all of them. Creating one nullable column per login method is awkward, and adding a new login method means changing the schema again. JSON avoids that problem.

```SQL
CREATE TABLE `tb_test`
(
`user_id`    bigint unsigned,
`login_info` json,
PRIMARY KEY (`user_id`)
);

INSERT INTO `tb_test` 
VALUES 
    (1, '{"tel": "13122335566", "QQ": "654321", "wechat": "jackfrued"}'),
    (2, '{"tel": "13599876543", "weibo": "wangdachui123"}');
```

To query a user's phone number and WeChat ID:

```SQL
SELECT `user_id`
     , JSON_UNQUOTE(JSON_EXTRACT(`login_info`, '$.tel')) AS phone
     , JSON_UNQUOTE(JSON_EXTRACT(`login_info`, '$.wechat')) AS wechat
FROM `tb_test`;
```

Because MySQL supports JSON, it also provides a full set of JSON functions. The query above can be written more concisely:

```SQL
SELECT `user_id`
     , `login_info` ->> '$.tel' AS phone
     , `login_info` ->> '$.wechat' AS wechat
  FROM `tb_test`;
```

Another use case is user profiling. If your product tags users for recommendation or segmentation, you can store those tags in a JSON array.

Create the tag table:

```SQL
CREATE TABLE `tb_tags`
(
`tag_id`   int unsigned NOT NULL COMMENT 'Tag ID',
`tag_name` varchar(20)  NOT NULL COMMENT 'Tag name',
PRIMARY KEY (`tag_id`)
);

INSERT INTO `tb_tags` (`tag_id`, `tag_name`) 
VALUES
    (1, 'Born in the 1970s'),
    (2, 'Born in the 1980s'),
    (3, 'Born in the 1990s'),
    (4, 'Born in the 2000s'),
    (5, 'Likes sports'),
    (6, 'Highly educated'),
    (7, 'Middle class'),
    (8, 'Owns a house'),
    (9, 'Owns a car'),
    (10, 'Likes movies'),
    (11, 'Likes online shopping'),
    (12, 'Frequently orders takeout');
```

Store user tags:

```SQL
CREATE TABLE `tb_users_tags`
(
`user_id`   bigint unsigned NOT NULL COMMENT 'User ID',
`user_tags` json            NOT NULL COMMENT 'User tags'
);

INSERT INTO `tb_users_tags`
VALUES
    (1, '[2, 6, 8, 10]'),
    (2, '[3, 10, 12]'),
    (3, '[3, 8, 9, 11]');
```

Some example queries:

1. Users who like movies (`10`):

```SQL
SELECT `user_id`
  FROM `tb_users_tags`
 WHERE 10 MEMBER OF (`user_tags`->'$');
```

2. Users who like movies and were born in the 1980s:

```SQL
SELECT `user_id`
  FROM `tb_users_tags`
 WHERE JSON_CONTAINS(`user_tags`->'$', '[2, 10]');
```

3. Users who are either movie lovers, born in the 1980s, or born in the 1990s:

```SQL
SELECT `user_id`
  FROM `tb_users_tags`
 WHERE JSON_OVERLAPS(user_tags->'$', '[2, 3, 10]');
```

> **Note**: `member of`, `json_contains`, and `json_overlaps` are all useful JSON tools. `json_contains` checks whether an array includes specific elements, while `json_overlaps` checks whether two arrays intersect.

### Window Functions

MySQL 8.0 supports window functions. Many commercial databases and several open-source databases have supported them for years. They are also called OLAP functions in some systems because they are closely tied to reporting and analytical work.

A window can be understood as a set of rows. A window function performs a calculation over that set for each row. This is different from an aggregate function:

- Aggregate functions reduce many rows into one result.
- Window functions return one result per row, so the total number of rows stays the same.

Basic syntax:

```SQL
<window_function> OVER (PARTITION BY <grouping_columns> ORDER BY <sorting_columns> ROWS BETWEEN ... AND ...)
<window_function> OVER (PARTITION BY <grouping_columns> ORDER BY <sorting_columns> RANGE BETWEEN ... AND ...)
```

Functions that can appear in a window include:

1. Dedicated window functions such as `lead`, `lag`, `first_value`, `last_value`, `rank`, `dense_rank`, and `row_number`.
2. Aggregate functions such as `sum`, `avg`, `max`, `min`, and `count`.

Below are two examples using the `hrs` database from the previous lesson.

Example 1: Query employees ranked 4th to 6th by salary.

```SQL
SELECT * 
  FROM (SELECT `ename`
             , `sal`
             , ROW_NUMBER() over (ORDER BY `sal` DESC) AS `rk`
	      FROM `tb_emp`) AS `temp`
 WHERE `rk` between 4 and 6;
```

> **Note**: `row_number()` assigns a row number to each record. Depending on your needs, you can replace it with `rank()` or `dense_rank()`.

Before MySQL 8, people often simulated ranking with user variables:

```SQL
select `rank`, `ename`, `sal` from (
       select @a:=@a+1 as `rank`, `ename`, `sal` 
       from `tb_emp`, (select @a:=0) as t1 order by `sal` desc
) as `temp` where `rank` between 4 and 6;
```

Example 2: Query the top 2 highest-paid employees in each department.

```SQL
select `ename`, `sal`, `dname` 
from (
    select 
        `ename`, `sal`, `dno`,
        rank() over (partition by `dno` order by `sal` desc) as `rank`
    from `tb_emp`
) as `temp` natural join `tb_dept` where `rank`<=2;
```

Before MySQL 8, that could be approximated like this:

```SQL
select `ename`, `sal`, `dname` from `tb_emp` as `t1` 
natural join `tb_dept` 
where (
        select count(*) from `tb_emp` as `t2` 
        where `t1`.`dno`=`t2`.`dno` and `t2`.`sal`>`t1`.`sal` 
)<2 order by `dno` asc, `sal` desc;
```
