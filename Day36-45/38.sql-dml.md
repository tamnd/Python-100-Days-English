## DML in Detail

Continuing with the school course-selection database created in the previous lesson, we will now explain how to use DML. DML helps us insert data into two-dimensional tables, `insert`, delete data from tables, `delete`, and update data in tables, `update`. Before running DML, switch to the `school` database with the following command.

```sql
USE `school`;
```

### The `insert` Operation

As the name suggests, `insert` is used to insert rows into a two-dimensional table. The supported forms include inserting a full row, inserting only part of a row, inserting multiple rows, and inserting the results of a query. The following SQL adds one college to the college table.

```sql
INSERT INTO `tb_college` 
VALUES
    (DEFAULT, 'College of Computer Science', 'A place to study computer science and technology');
```

Since the primary key in the college table is an auto-incrementing field, `default` tells MySQL to use the default value for that column. The same operation can also be written as follows.

```sql
INSERT INTO `tb_college` (`col_name`, `col_intro`) 
VALUES 
    ('College of Computer Science', 'A place to study computer science and technology');
```

We recommend the second style, explicitly specifying which columns are being assigned. That way, you do not have to follow the original column order from the table definition. Instead, you can assign values in the order listed before `values`. Keep in mind, however, that apart from columns that allow `null` or have default values, every other column must be listed and assigned a value. If you want to insert multiple records at once, you can follow `values` with multiple tuples to perform a batch insert, as shown below.

```sql
INSERT INTO `tb_college` 
    (`col_name`, `col_intro`) 
VALUES 
    ('College of Foreign Languages', 'A college for studying foreign languages'),
    ('College of Economics and Management', 'Economics for the nation, governance for the country; management science as a path to national strength'),
    ('College of Physical Education', 'Develop sports and improve physical fitness');
```

When inserting data, remember that primary keys cannot be duplicated. If the inserted data has the same primary key as an existing record in the table, the `insert` operation raises a Duplicate Entry error. Also remember that if an `insert` operation omits some columns, those columns must either allow `null` or have default values, otherwise an error will also occur. In business systems, if we want the `insert` operation to avoid affecting the performance of other operations, especially later `select` queries, we can add `low_priority` between `insert` and `into` to lower its priority. The same idea also applies to the `delete` and `update` operations introduced below.

Suppose there is a table named `tb_temp` with two columns, `a` and `b`, which store college names and college descriptions. We can also obtain data from `tb_temp` through a query and insert that result into the college table, as shown below. The `select` used here is DQL, which we will explain in detail in the next lesson.

```sql
INSERT INTO `tb_college`
    (`col_name`, `col_intro`)
SELECT `a`, `b` 
  FROM `tb_temp`;
```

### The `delete` Operation

If we need to delete data from a table, we can use the `delete` operation. It can remove specified rows or all rows. For example, if we want to delete the college whose ID is `1`, we can use the SQL below.

```sql
DELETE
  FROM `tb_college`
 WHERE col_id=1;
```

Notice that the `where` clause in the `delete` statement specifies the condition, and only rows that satisfy that condition are removed. If we accidentally wrote the SQL below instead, all records in the college table would be deleted. That is very dangerous, and in real work it is usually not something we want to do.

```sql
DELETE
  FROM `tb_college`;
```

It should also be pointed out that even if all data is deleted, the `delete` operation does not delete the table itself, nor does it reset the value of an `AUTO_INCREMENT` column. If you need to delete all data and also reset the `AUTO_INCREMENT` value, you can use `truncate table`. In essence, `truncate` deletes the original table and recreates it, which is actually faster because it does not need to remove rows one by one. But remember clearly that `truncate table` is very dangerous, because it deletes all the data, and once the original table is gone, recovering mistakenly deleted data becomes much more difficult.

### The `update` Operation

If we want to modify data in a table, we can use `update`. It is used to modify specified rows, or if misused, all rows. For example, suppose we want to change the student named Yang Guo to Yang Xiao, and we assume the student ID of Yang Guo is `1001`. The code is shown below.

```sql
UPDATE `tb_student`
   SET `stu_name`='Yang Xiao'
 WHERE `stu_id`=1001;
```

Notice the `where` clause above. We use the student ID as the condition to select the correct student, and then the assignment in the `set` clause changes the name to Yang Xiao. Why not use the name directly as the condition? Because the student table might contain more than one student named Yang Guo. If we used `stu_name` as the condition, our `update` might end up changing multiple rows, which is clearly not what we want. Another point worth noting is the `set` keyword. In SQL, `=` normally means equality comparison, not assignment. Only when it appears after `set` does it act as assignment.

If we want to update both a student's name and birth date at the same time, we can make a small modification to the previous `update` statement, as shown below.

```sql
UPDATE `tb_student`
   SET `stu_name`='Yang Xiao'
     , `stu_birth`='1975-12-29'
 WHERE `stu_id`=1001;
```

An `update` statement can also use query results to obtain the data used for updating target rows. Interested readers can explore that on their own. In practice, `update` statements almost always include a `where` clause, because operations that update an entire table are rarely needed in real work. This is something you should pay close attention to.

### Summary

DML is used to manipulate table data. Through `insert`, `delete`, and `update`, we can add, remove, and modify records. When writing DML, conditions such as `where` clauses are especially important, because a careless statement can affect far more data than intended.
