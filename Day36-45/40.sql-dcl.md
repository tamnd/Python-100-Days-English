## DCL in Detail

Database servers usually contain very important data, so access control matters. DCL solves this problem by granting permissions to users or revoking permissions from them. For a DBA, privilege management is a core security task. In simple terms, DCL lets trusted users access what they need, blocks untrusted users, and follows the principle of least privilege.

### Creating a User

The following statement creates a user and sets a password:

```SQL
CREATE USER 'wangdachui'@'%' IDENTIFIED BY 'Wang.618';
```

This creates a user named `wangdachui` who can connect from any host because `%` is a wildcard.

If you want to restrict that user to the `192.168.0.x` subnet:

```SQL
DROP USER IF EXISTS 'wangdachui'@'%';

CREATE USER 'wangdachui'@'192.168.0.%' IDENTIFIED BY 'Wang.618';
```

At this point the account still cannot do much, because it has not been granted any privileges.

### Granting Privileges

Grant `SELECT` on the `tb_college` table in the `school` database:

```SQL
GRANT SELECT ON `school`.`tb_college` TO 'wangdachui'@'192.168.0.%';
```

Grant query permission on all objects in the `school` database:

```SQL
GRANT SELECT ON `school`.* TO 'wangdachui'@'192.168.0.%';
```

Grant insert, delete, and update privileges:

```SQL
GRANT INSERT, DELETE, UPDATE ON `school`.* TO 'wangdachui'@'192.168.0.%';
```

Grant DDL-related privileges:

```SQL
GRANT CREATE, DROP, ALTER ON `school`.* TO 'wangdachui'@'192.168.0.%';
```

Grant every privilege on every database object:

```SQL
GRANT ALL PRIVILEGES ON *.* TO 'wangdachui'@'192.168.0.%';
```

In most real systems you should not do this for an ordinary account. Give users only the permissions they actually need.

### Revoking Privileges

Revoke insert, delete, and update permissions from the `school` database:

```SQL
REVOKE INSERT, DELETE, UPDATE ON `school`.* FROM 'wangdachui'@'192.168.0.%';
```

Revoke all privileges:

```SQL
REVOKE ALL PRIVILEGES ON *.* FROM 'wangdachui'@'192.168.0.%';
```

Privilege information may be cached, so after granting or revoking permissions, you can run:

```SQL
FLUSH PRIVILEGES;
```

This makes the changes take effect immediately.
