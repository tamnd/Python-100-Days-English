## DCL in Detail

Database servers usually contain very important data, and access control can be used to ensure the safety of that data. DCL is the part of SQL that solves this problem. It can grant access privileges to specified users or revoke privileges from specified users. DCL is very important for database administrators because user privilege management is directly related to database security. Put simply, through DCL we can allow trusted users to access the database, block untrusted users, and apply the principle of least privilege so that every user has only the permissions they actually need.

### Creating Users

We can use the following SQL to create a user and specify an access password.

```sql
CREATE USER 'wangdachui'@'%' IDENTIFIED BY 'Wang.618';
```

The SQL above creates a user named `wangdachui`, gives it the password `Wang.618`, and allows that user to access the database server from any host, because `%` after `@` is the wildcard for any number of characters. If we want to restrict `wangdachui` so that it can only access the server from the `192.168.0.x` subnet, we can change the SQL as follows.

```sql
DROP USER IF EXISTS 'wangdachui'@'%';

CREATE USER 'wangdachui'@'192.168.0.%' IDENTIFIED BY 'Wang.618';
```

At this point, if we log in to the database server with the `wangdachui` account, we can barely do anything, because that account does not yet have any privileges.

### Granting Privileges

We can use the statement below to grant `wangdachui` permission to query the college table, `tb_college`, in the `school` database.

```sql
GRANT SELECT ON `school`.`tb_college` TO 'wangdachui'@'192.168.0.%';
```

We can also allow `wangdachui` to query all objects in the `school` database, as shown below.

```sql
GRANT SELECT ON `school`.* TO 'wangdachui'@'192.168.0.%';
```

If we want `wangdachui` to also have `insert`, `delete`, and `update` privileges, we can grant them in the following way.

```sql
GRANT INSERT, DELETE, UPDATE ON `school`.* TO 'wangdachui'@'192.168.0.%';
```

If we also want to grant `wangdachui` permission to execute DDL, we can use the SQL below.

```sql
GRANT CREATE, DROP, ALTER ON `school`.* TO 'wangdachui'@'192.168.0.%';
```

If we want the `wangdachui` account to have every privilege on every object in every database, we can execute the following statement. In general, however, we should not do this, because as mentioned earlier, permissions should only be sufficient for the task at hand. An ordinary account should not have this much power.

```sql
GRANT ALL PRIVILEGES ON *.* TO 'wangdachui'@'192.168.0.%';
```

### Revoking Privileges

If we want to revoke `wangdachui`'s `insert`, `delete`, and `update` privileges on the `school` database, we can use the operation below.

```sql
REVOKE INSERT, DELETE, UPDATE ON `school`.* FROM 'wangdachui'@'192.168.0.%';
```

If we want to revoke all privileges, we can do it as follows.

```sql
REVOKE ALL PRIVILEGES ON *.* FROM 'wangdachui'@'192.168.0.%';
```

It should be noted that because the database may cache user privileges, after granting or revoking privileges, we can execute the following statement to make the new privileges take effect immediately.

```sql
FLUSH PRIVILEGES;
```
