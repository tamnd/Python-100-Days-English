## File Reading/Writing and Exception Handling

In real-world development, we often encounter situations where data must be persisted. Persistence means moving data from a storage medium that cannot preserve data for long, usually memory, to a storage medium that can preserve it for a long time, usually a hard disk. The most direct and simplest way to achieve persistence is to save data into **files** through the **file system**.

A computer **file system** is a way of storing and organizing computer data that makes data access and lookup easier. The file system uses the logical concepts of **files** and **tree-structured directories** in place of the physical data blocks on hard disks, optical discs, flash storage, and similar devices. When users save data through the file system, they do not need to care which physical block the data is stored in; they only need to remember the file path and file name. Before writing new data, users also do not need to care which disk blocks are unused. Storage-space management on the disk, including allocation and release, is handled automatically by the file system. Users only need to remember which file the data was written to.

### Opening and Closing Files

With a file system, we can read and write data very conveniently through files. In Python, file operations are very easy to perform. We can use Python's built-in `open` function to open a file. When using `open`, we can specify details such as the **file name**, **mode**, and **character encoding** through its arguments, and then perform reading or writing operations on the file. The mode refers to what kind of file to open, text or binary, and what kind of operation to perform, read, write, or append. The common modes are listed below.

| Mode | Meaning |
| -------- | -------------------------------- |
| `'r'`    | Read (default)                    |
| `'w'`    | Write, truncating existing content first |
| `'x'`    | Write, but raise an exception if the file already exists |
| `'a'`    | Append, writing content to the end of an existing file |
| `'b'`    | Binary mode                       |
| `'t'`    | Text mode (default)                 |
| `'+'`    | Update mode, allowing both reading and writing |

When the file opened by `open` is a text file, we can use the `encoding` parameter to specify the character encoding used for reading and writing. If you are not familiar with concepts such as character sets and character encodings, you can read [Character Sets and Character Encodings](https://www.cnblogs.com/skynet/archive/2011/05/03/2035105.html); we will not go into detail here.

If `open` succeeds, it returns a file object, and through that object we can read from and write to the file. If opening the file fails, `open` raises an exception, which we will explain later. To close an opened file, we can use the file object's `close` method, which releases the file when the operation is finished.

### Reading and Writing Text Files

When we use `open` to open a text file, we need to specify the file name and set the mode to `'r'`; if we do not specify it, the default is also `'r'`. If we need to specify a character encoding, we can pass the `encoding` argument. If we do not specify it, the default value is `None`, which means the operating system's default encoding will be used when reading the file. One thing to keep in mind is that if we cannot guarantee that the encoding used to save the file matches the encoding specified by the `encoding` argument, reading the file may fail because the characters cannot be decoded.

The example below shows how to read a plain-text file. A plain-text file generally contains only raw encoded characters and, unlike rich text, does not contain formatting control information, so it can be read directly by the simplest text editors.

```python
file = open('ToTheOakTree.txt', 'r', encoding='utf-8')
print(file.read())
file.close()
```

> **Note**: *To the Oak Tree* is a love poem written by Shu Ting in March 1977, and it is also one of my favorite modern poems.

In addition to using the file object's `read` method, we can also read a text file line by line with a `for-in` loop, or read all lines into a list with `readlines`, as shown below.

```python
file = open('ToTheOakTree.txt', 'r', encoding='utf-8')
for line in file:
    print(line, end='')
file.close()

file = open('ToTheOakTree.txt', 'r', encoding='utf-8')
lines = file.readlines()
for line in lines:
    print(line, end='')
file.close()
```

If we want to write content into a file, we can open it in mode `'w'` or `'a'`. The former truncates the existing text and writes new content, while the latter appends new content to the end of what is already there.

```python
file = open('ToTheOakTree.txt', 'a', encoding='utf-8')
file.write('\nTitle: To the Oak Tree')
file.write('\nAuthor: Shu Ting')
file.write('\nDate: March 1977')
file.close()
```

### Exception Handling

Please note that in the code above, if the file specified by `open` does not exist or cannot be opened, an exception will be raised and the program will crash. To make our code more robust and fault tolerant, we can **use Python's exception mechanism to properly handle code that may fail at runtime**. Python has five keywords related to exceptions: `try`, `except`, `else`, `finally`, and `raise`. Let us first look at the following example and then explain how they are used.

```python
file = None
try:
    file = open('ToTheOakTree.txt', 'r', encoding='utf-8')
    print(file.read())
except FileNotFoundError:
    print('Cannot open the specified file!')
except LookupError:
    print('An unknown encoding was specified!')
except UnicodeDecodeError:
    print('A decoding error occurred while reading the file!')
finally:
    if file:
        file.close()
```

In Python, we can place code that may fail at runtime inside a `try` block, and follow it with one or more `except` blocks to catch exceptions and handle them accordingly. For example, in the code above, a missing file raises `FileNotFoundError`, an unknown encoding raises `LookupError`, and if the file cannot be decoded with the specified encoding while being read, `UnicodeDecodeError` is raised. Therefore, we added three `except` blocks after `try` to handle these three different situations.

After the `except` blocks, we can also add an `else` block. The code in `else` is executed only when no exception occurs in the `try` block, and exceptions raised inside `else` are not caught again by the preceding `except` clauses. In other words, if an exception occurs there, the program will terminate and report it. Finally, we use the `finally` block to close the opened file and release the external resource obtained by the program. Since the code in `finally` runs regardless of whether the program completes normally or with an exception, even if `sys.exit` is called to terminate the program, we often call it the "always execute" block, and it is especially suitable for releasing external resources.

From the inheritance structure above, we can see that all exceptions in Python are subtypes of `BaseException`. It has four direct subclasses: `SystemExit`, `KeyboardInterrupt`, `GeneratorExit`, and `Exception`. Among them, `SystemExit` indicates that the interpreter is being asked to exit, `KeyboardInterrupt` indicates that the user interrupted program execution by pressing `Ctrl+C`, and `GeneratorExit` indicates that a generator is exiting after an exception notification. It is fine if you do not fully understand these yet. The important one here is `Exception`, which is the parent type for ordinary exceptions, and many exception classes inherit from it directly or indirectly. If Python's built-in exceptions cannot meet the needs of an application, we can define our own exception types, and custom exceptions should also inherit directly or indirectly from `Exception`. We can also override or add methods when necessary.

In Python, we can use the `raise` keyword to raise an exception, and the caller can catch and handle it through a `try...except...` structure. For example, when the conditions for a function to run are not satisfied, we can raise an exception to tell the caller what the problem is, and the caller can recover from that problem by catching and handling the exception. The code below shows how to define and raise an exception.

```python
class InputError(ValueError):
    """Custom exception type"""
    pass


def fac(num):
    """Calculate factorial"""
    if num < 0:
        raise InputError('Factorial can only be calculated for non-negative integers')
    if num in (0, 1):
        return 1
    return num * fac(num - 1)
```

We can call the `fac` function below, catch the input error with `try...except...`, and print the exception object. If the input is correct, the program computes the factorial and terminates.

```python
flag = True
while flag:
    num = int(input('n = '))
    try:
        print(f'{num}! = {fac(num)}')
        flag = False
    except InputError as err:
        print(err)
```

### Context Manager Syntax

For the file object returned by `open`, we can also use the `with` context manager syntax so that the file object's `close` method is executed automatically after the file operation is finished. This makes the code simpler and more elegant, because we no longer need a `finally` block to close the file and release the resource. Keep in mind that not every object can be used with `with`; only objects that follow the **context manager protocol**, meaning they provide the magic methods `__enter__` and `__exit__`, can be used in this syntax. Python's standard-library `contextlib` module also provides support for context-manager usage, and we will cover that when we need it later.

The code rewritten with `with` is shown below.

```python
try:
    with open('ToTheOakTree.txt', 'r', encoding='utf-8') as file:
        print(file.read())
except FileNotFoundError:
    print('Cannot open the specified file!')
except LookupError:
    print('An unknown encoding was specified!')
except UnicodeDecodeError:
    print('A decoding error occurred while reading the file!')
```

### Reading and Writing Binary Files

Reading and writing binary files is similar to reading and writing text files, but there are two things to note. First, when using `open`, the mode is `'rb'` for reading and `'wb'` for writing. Second, when reading and writing text files, the return value of `read` and the argument of `write` are `str` objects, but when reading and writing binary files, the return value of `read` and the argument of `write` are bytes-like objects. The following code copies the image file `guido.jpg` in the current path into a file named `guido-copy.jpg`.

```python
try:
    with open('guido.jpg', 'rb') as file1:
        data = file1.read()
    with open('guido-copy.jpg', 'wb') as file2:
        file2.write(data)
except FileNotFoundError:
    print('Cannot open the specified file.')
except IOError:
    print('An error occurred while reading or writing the file.')
print('Program execution finished.')
```

If you want to copy a large binary file, reading all of the data into memory at once may cause excessive memory usage. To reduce memory overhead, we can read and write the file in chunks, as shown below.

```python
try:
    with open('guido.jpg', 'rb') as file1, open('guido-copy.jpg', 'wb') as file2:
        data = file1.read(512)
        while data:
            file2.write(data)
            data = file1.read(512)
except FileNotFoundError:
    print('Cannot open the specified file.')
except IOError:
    print('An error occurred while reading or writing the file.')
print('Program execution finished.')
```

### Summary

By reading and writing files, we can persist data. In Python, the `open` function gives us a file object, and then we can use the file object's `read` and `write` methods to perform file operations. Problems that occur at runtime can be handled through Python's exception mechanism, whose core keywords are `try`, `except`, `else`, `finally`, and `raise`. One last reminder: **do not use exceptions to handle normal business logic or control normal program flow**. That is a common beginner mistake.
