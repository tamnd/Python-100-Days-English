## An Overview of Web Data Collection

A crawler, also called a spider, is an automated program that browses websites according to rules and collects data. Crawlers are widely used in search engines and data gathering systems. Because web pages contain links to other pages, a crawler can continue discovering new resources and collecting information across the web.

### Where Crawlers Are Used

In an ideal world, every content provider would offer official APIs for all allowed data access. In reality, APIs often have strict limits on:

- which data can be accessed
- how often it can be fetched

For many businesses, timely access to industry data and competitor data is important, and crawlers become a practical tool when no suitable API exists.

Typical applications:

1. Search engines
2. News aggregation
3. Social applications
4. Public-opinion monitoring
5. Industry data collection

### Legal and Ethical Considerations

People often joke that writing crawlers is risky. In practice, the legal situation depends on what is being collected and how it is being used.

Key points:

1. Web crawling is still a gray area in many places. Industry norms such as the Robots protocol exist, but legal frameworks are still evolving.
2. If a crawler only accesses publicly visible frontend data, the legal risk is generally lower than when it targets private backend data.
3. Respect `robots.txt`, rate limits, and intellectual-property rights.
4. Avoid aggressive behavior that could damage another party’s infrastructure.
5. Be cautious about publishing crawler code publicly if it targets real commercial systems.

### The Robots Protocol

Many websites define a `robots.txt` file. It is a gentleman’s agreement rather than a hard technical barrier, but responsible crawlers should pay attention to it.

Example restrictions may:

- block specific user agents
- block certain paths
- expose sitemap URLs

### HTTP Refresher

Since most crawlers operate over the web, understanding HTTP is essential.

HTTP is built on top of TCP and is used to exchange HTML, JSON, images, and other resources between browsers and servers.

An HTTP request usually contains:

- request line
- headers
- blank line
- optional body

An HTTP response usually contains:

- status line
- headers
- blank line
- body

### The Basic Crawler Workflow

A basic crawler usually includes three parts:

1. data acquisition
2. data parsing
3. data storage

General workflow:

1. Define seed pages and fetch them.
2. Retry failed downloads when needed.
3. Set headers, proxies, or other disguise mechanisms if necessary.
4. Decode and parse the response.
5. Extract useful data.
6. Extract and normalize links for further crawling.
7. Persist the useful information.

Larger crawler systems may add schedulers, monitoring services, and distributed execution.
