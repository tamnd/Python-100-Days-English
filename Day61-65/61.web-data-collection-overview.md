## An Overview of Web Data Collection

A crawler, also called a spider, is a robot program that automatically browses websites according to rules and gets the information it needs. It is widely used in search engines and data collection. Since web pages contain hyperlinks to other pages, a crawler can keep getting the addresses of other pages and continue collecting data. That is why the process feels a bit like a crawler or spider wandering around the web.

### Where Crawlers Are Used

In an ideal world, every ICP, or Internet Content Provider, would offer official APIs for the data it allows other programs to get. In reality, APIs often have strict limits on:

- which data can be accessed
- how often it can be fetched

For many companies, getting industry data and competitor data in time is very important. For many of them, data is naturally one of their weak points. In that situation, using crawlers properly to get data and pull out business value becomes very important.

Typical applications:

1. Search engines
2. News aggregation
3. Social applications
4. Public-opinion monitoring
5. Industry data collection

### Legal and Ethical Considerations

People often joke that writing crawlers is risky. In practice, the legal situation depends on what is being collected and how it is being used.

People often joke that "if you write crawlers too well, you may end up in trouble". So is writing crawler code illegal? You can look at it from a few angles.

Key points:

1. Web crawling is still a gray area in many places. The internet world has its own rule of conduct, namely the Robots protocol, but the legal side is still being built and improved.
2. If a crawler gets frontend data that is publicly visible, instead of private backend data, the legal risk is usually lower.
3. When crawling a site, you should respect the Robots protocol, control the crawling speed, and respect the site's intellectual-property rights when using the data.
4. Hiding your identity to a reasonable degree is often necessary, and it is better not to give the other side evidence that your crawler damaged their servers or other property.
5. Do not casually open-source or publicly show crawler code for real commercial targets on public platforms, because that often brings unnecessary trouble.

### The Robots Protocol

Many websites define a `robots.txt` file. It is a gentleman’s agreement rather than a hard technical barrier, but responsible crawlers should pay attention to it.

Example restrictions may:

- block specific user agents
- block certain paths
- expose sitemap URLs

### HTTP Refresher

Since most crawlers operate over the web, understanding HTTP is essential.

HTTP is built on top of TCP and is used to exchange HTML, JSON, images, and other resources between browsers and servers.

An HTTP request usually contains:

- request line
- headers
- blank line
- optional body

An HTTP response usually contains:

- status line
- headers
- blank line
- body

### The Basic Crawler Workflow

A basic crawler usually includes three parts:

1. data acquisition
2. data parsing
3. data storage

General workflow:

1. Define seed pages and fetch them.
2. Retry failed downloads when needed.
3. Set headers, proxies, or other disguise mechanisms if necessary.
4. Decode and parse the response.
5. Extract useful data.
6. Extract and normalize links for further crawling.
7. Persist the useful information.

More advanced crawlers may also use concurrency or distributed techniques, so they may need a scheduler, background management tools, and monitoring support.
