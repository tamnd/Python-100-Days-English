## Concurrent Programming in Python, Part 2

Because of the GIL in CPython, multithreading does not fully utilize multiple CPU cores for CPU-bound work. If you need true multi-core execution, multiprocessing is often the better option.

### Creating Processes

The `multiprocessing.Process` class is similar to `threading.Thread` in usage:

```python
from multiprocessing import Process, current_process
from time import sleep


def sub_task(content, nums):
    print(f'PID: {current_process().pid}')
    print(f'Name: {current_process().name}')
    counter, total = 0, nums.pop(0)
    print(f'Loop count: {total}')
    sleep(0.5)
    while counter < total:
        counter += 1
        print(f'{counter}: {content}')
        sleep(0.01)


def main():
    nums = [20, 30, 40]
    Process(target=sub_task, args=('Ping', nums)).start()
    Process(target=sub_task, args=('Pong', nums)).start()
    sub_task('Good', nums)
```

On Unix-like systems, `os.fork()` is another way to create processes, but it is not portable to Windows. For portability, prefer:

- `Process`
- subclassing `Process`
- `ProcessPoolExecutor`

### Threads vs. Processes

For I/O-bound tasks such as crawlers, multiprocessing usually does not provide much advantage over threads. For CPU-bound tasks, it often does.

The lesson demonstrates this with prime-number checking:

- thread pool version: CPU utilization stays near one core
- process pool version: CPU utilization can spread across multiple cores

The conclusion is straightforward:

- use threads for I/O-heavy work
- use processes for CPU-heavy work

Typical CPU-bound workloads:

- scientific computing
- image processing
- audio/video encoding and decoding
- compression

### Inter-Process Communication

Processes do not share memory directly, so communication has to be explicit.

A broken approach:

```python
counter = 0
```

Each child process gets its own copy, so modifying `counter` in one process does not affect the others.

A working approach is to use `multiprocessing.Queue`:

```python
import time
from multiprocessing import Process, Queue


def sub_task(content, queue):
    counter = queue.get()
    while counter < 50:
        print(content, end='', flush=True)
        counter += 1
        queue.put(counter)
        time.sleep(0.01)
        counter = queue.get()
```

This lets multiple processes exchange data safely.

### Summary

Use multithreading when:

1. the program spends a lot of time waiting for I/O
2. shared mutable state is important

Use multiprocessing when:

1. the workload is CPU-bound
2. the input can be partitioned and results combined
3. the extra memory cost is acceptable
