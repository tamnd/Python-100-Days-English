## Concurrent Programming in Python, Part 1

Modern computers are multi-CPU or multi-core systems, and modern operating systems support multitasking. That means applications can split work into smaller units and execute them concurrently or in parallel, improving both performance and user experience.

To understand concurrency in Python, start with two concepts:

- process
- thread

### Processes and Threads

A process is a running program with its own address space, stack, and execution state. Processes are the basic units to which the operating system allocates resources.

A process can create other processes using mechanisms such as `fork` or `spawn`, but separate processes do not share memory directly. Inter-process communication typically requires:

- pipes
- signals
- sockets
- queues

A thread is an execution path inside a process. Threads within the same process share memory and context, so communication is easier than between processes.

Important distinction:

- **concurrency**: tasks make progress during overlapping periods, often via rapid context switching
- **parallelism**: tasks literally execute at the same time on multiple processors

### Multithreading

Python’s `threading.Thread` makes multithreaded programming straightforward.

Single-threaded example:

```python
import random
import time


def download(*, filename):
    start = time.time()
    print(f'Start downloading {filename}.')
    time.sleep(random.randint(3, 6))
    print(f'{filename} downloaded.')
    end = time.time()
    print(f'Download time: {end - start:.3f}s.')
```

Using three downloads sequentially means the total time is roughly the sum of all three waits.

Threaded version:

```python
import random
import time
from threading import Thread


def download(*, filename):
    start = time.time()
    print(f'Start downloading {filename}.')
    time.sleep(random.randint(3, 6))
    print(f'{filename} downloaded.')
    end = time.time()
    print(f'Download time: {end - start:.3f}s.')


def main():
    threads = [
        Thread(target=download, kwargs={'filename': 'Python Guide.pdf'}),
        Thread(target=download, kwargs={'filename': 'MySQL Course.avi'}),
        Thread(target=download, kwargs={'filename': 'Linux Tutorial.mp4'})
    ]
    start = time.time()
    for thread in threads:
        thread.start()
    for thread in threads:
        thread.join()
    end = time.time()
    print(f'Total time: {end - start:.3f}s.')
```

Because the downloads do not depend on each other, running them concurrently reduces the overall wait.

### Creating Threads in Different Ways

You can create threads by:

1. instantiating `Thread`
2. subclassing `Thread` and overriding `run`
3. using a thread pool

Subclass example:

```python
class DownloadThread(Thread):
    def __init__(self, filename):
        self.filename = filename
        super().__init__()

    def run(self):
        ...
```

Thread pool example:

```python
from concurrent.futures import ThreadPoolExecutor
```

Thread pools are usually preferable because threads are expensive to create and destroy repeatedly.

### Daemon Threads

A daemon thread is not meant to keep a program alive by itself. When all non-daemon threads finish, daemon threads are terminated automatically.

Example:

```python
Thread(target=display, args=('Ping', ), daemon=True).start()
```

### Resource Contention

Once multiple threads access shared data, resource contention becomes a real problem. That topic naturally leads to synchronization primitives such as locks, which are covered by the broader concurrency discussion even if the original excerpt here had not yet reached the full locking section.
