## Concurrent Programming in Python, Part 1

Modern computers are already multi-CPU or multi-core systems, and modern operating systems basically all support multitasking. That means we can run multiple programs at the same time, and we can also break one program into several relatively independent sub-tasks and let them run in parallel or concurrently. This can shorten execution time and also give users a better experience.

To understand concurrency in Python, start with two concepts:

- process
- thread

### Processes and Threads

A process is a running program with its own address space, data stack, and execution state. It is the basic unit to which the operating system allocates memory and other resources.

A process can create other processes using mechanisms such as `fork` or `spawn`, but separate processes do not share memory directly. Inter-process communication typically requires:

- pipes
- signals
- sockets
- queues

A thread is an execution path inside a process. Threads in the same process share the same context, so information sharing and communication are easier than between processes.

Here we need to stress two ideas again:

- **concurrency**: at one moment only one instruction may actually be running, but the instructions of several tasks are switched very quickly so that they look as if they are running together
- **parallelism**: at one moment multiple instructions are really running on multiple processors at the same time

### Multithreading

Python’s `threading.Thread` makes multithreaded programming straightforward.

Single-threaded example:

```python
import random
import time


def download(*, filename):
    start = time.time()
    print(f'Start downloading {filename}.')
    time.sleep(random.randint(3, 6))
    print(f'{filename} downloaded.')
    end = time.time()
    print(f'Download time: {end - start:.3f}s.')
```

Using three downloads sequentially means the total time is roughly the sum of all three waits.

Threaded version:

```python
import random
import time
from threading import Thread


def download(*, filename):
    start = time.time()
    print(f'Start downloading {filename}.')
    time.sleep(random.randint(3, 6))
    print(f'{filename} downloaded.')
    end = time.time()
    print(f'Download time: {end - start:.3f}s.')


def main():
    threads = [
        Thread(target=download, kwargs={'filename': 'Python Guide.pdf'}),
        Thread(target=download, kwargs={'filename': 'MySQL Course.avi'}),
        Thread(target=download, kwargs={'filename': 'Linux Tutorial.mp4'})
    ]
    start = time.time()
    for thread in threads:
        thread.start()
    for thread in threads:
        thread.join()
    end = time.time()
    print(f'Total time: {end - start:.3f}s.')
```

Because the downloads do not depend on each other, running them concurrently reduces the overall wait.

### Creating Threads in Different Ways

You can create threads by:

1. instantiating `Thread`
2. subclassing `Thread` and overriding `run`
3. using a thread pool

Subclass example:

```python
class DownloadThread(Thread):
    def __init__(self, filename):
        self.filename = filename
        super().__init__()

    def run(self):
        ...
```

Thread pool example:

```python
from concurrent.futures import ThreadPoolExecutor
```

Thread pools are usually the better choice because creating and destroying threads has a noticeable cost, and frequent thread creation and release is usually not ideal.

### Daemon Threads

A daemon thread is not meant to keep a program alive by itself. When all non-daemon threads finish, daemon threads are terminated automatically.

Example:

```python
Thread(target=display, args=('Ping', ), daemon=True).start()
```

### Resource Contention

Once multiple threads access shared data, resource contention becomes a real problem. If there is no proper way to protect the shared resource, you may get unexpected results. The original lesson goes on to show the classic lost-update problem with a bank account and then fixes it with `RLock`.
