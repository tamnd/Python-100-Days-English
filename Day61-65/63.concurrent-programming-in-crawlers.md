## Applying Concurrency to Crawlers

Python supports several concurrency tools:

- multithreading
- multiprocessing
- asynchronous I/O

For crawlers, which are usually I/O-bound, multithreading and async I/O are the most relevant, because when one part is blocked by I/O, another part can still keep running.

The lesson compares three versions of an image crawler that downloads pictures from the `360 Image` site. The page itself uses Ajax and waterfall-style loading, so the image information is actually returned by a JSON API.

### Single-Threaded Version

The single-threaded crawler:

- fetches JSON page data
- iterates through image URLs
- downloads each image one by one

This version is simple but slow because it waits for every network request sequentially.

### Multithreaded Version

Using `ThreadPoolExecutor` improves performance by downloading multiple images concurrently:

```python
from concurrent.futures import ThreadPoolExecutor
```

Compared with the single-threaded version, total execution time drops sharply because waiting on one request does not stop the others.

### Async I/O Version

The lesson also implements an async version using:

- `aiohttp`
- `aiofile`

Install them:

```bash
pip install aiohttp aiofile
```

The async version uses:

- `aiohttp.ClientSession` for non-blocking HTTP requests
- `aiofile.async_open` for asynchronous file writing
- an event loop to coordinate all the coroutines

### Conclusion

In the original measurements:

- the single-threaded crawler was much slower
- the multithreaded and async versions were both dramatically faster
- async I/O achieved similar speed with less CPU overhead than threads

The key takeaway is that for I/O-bound crawling, both threads and async I/O work well, but async I/O often uses resources more efficiently. In the original measurements, the single-threaded version took about 21 seconds, while the multithreaded and async versions both finished in about 3 seconds.
